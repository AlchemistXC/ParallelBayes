# 论证链

- 已知：时间并行能在特定设置中降低轨迹执行延迟；模型几何、批量、资源、容差和编译开销决定收益边界。
- 张力：较短执行深度不保证较低完整推断成本；数值求解速度也不保证相同统计输出。
- 核心问题：给定目标、转移核与资源，在哪些条件下时间并行降低经核验输出的完整成本；这种收益是否保留到共同后验函数误差？
- 支撑路径 A：固定坐标、调参、随机输入与步数 → 同核执行比较 → 核验成本与失败区间。
- 支撑路径 B：固定推断任务、硬件与精度 → 允许不同合理核与调参 → 完整工作流误差/成本比较。
- 候选贡献：连接两条路径，报告轨迹核验、端到端误差和资源取舍的共同实验，而非重新命名既有算法。
- 反论点：已有比较平台和相关实验；包装接口未必有发表增量；单卡/少量模型不支持普适结论。
- 应对：使用前作组件与模型，明确差异；冻结基准协议，保留反例、失败和不确定性；软件开发本身不算算法创新。
- 决策：先完成最小原生 JAX 闭环和独立 Picard 正确性验证；再做 Stan/R 接口；选择器后置。
