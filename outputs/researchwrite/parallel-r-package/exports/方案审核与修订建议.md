# 并行 MCMC 的 R 包与基准研究：方案审核及修订建议

2026-10-03。依据：用户提供的方案、现有论文与精读卡、官方软件文档及固定提交源代码。使用 nature-academic-search 和 researchwrite；工程与统计协议分别进行了独立 AI 专项审查。本轮没有安装采样库或运行性能实验。

后续状态：审核意见现已落实为[研究与开发计划 v1.0](研究与开发计划.md)及[开发任务清单](开发任务清单.md)。本文保留为历史审核依据，日常实施以新版计划为准。

## 结论

**这个方向可以推进，原评价的主线基本成立，但它还不是可直接执行的开发与实验协议。** 建议保留“平台—基准—可选配置选择”的顺序；标准 Stan 作为用户模型入口，原生 JAX 作为首条时间并行实验路径；暂不开发新语言。应先完成小规模正确性与成本验证，再决定扩展 R 包及改写论文。

需要修订的重点不是再加算法，而是三件事：公开研究代码还需要多少实现与审计工作；有限容差、回退和实时时限究竟返回什么统计对象；实验能产出哪些前作尚未提供的、可被反例推翻的结论。**“做了 R 包”不自动构成算法创新，“跨模型比较”也不能直接声明首次。** 软件研究能增加原创证据的可能性，但目前不能判断它比现有综述更容易发表。

用户已确认可用 Mac/CPU，以及 AMD CPU＋RTX 5080 的 Windows 11 台式机。这足以启动验证，无须先购买硬件；具体软件栈与可达到的模型规模仍待实测。

## 1. 原评价中应保留的判断

以下设计合理：不先开发通用概率编程语言；分离模型、转移核与执行器；分开同核执行收益和跨核推断收益；固定实际随机输入而非仅固定整数种子；计入编译、预热、探测、传输和失败；把自动配置放在平台及基准之后；按模型族留出测试。

这与现稿一致。现稿已明确自身是证据综合，也在第 7.2 节提出计入探测开销的资源配置问题。软件研究可以沿该问题开展，但必须用新实验支持新贡献。[当前主稿](../../../../manuscript/中文综述.tex)

## 2. 六项会改变路线的核查结果

### 2.1 Stan 是合适入口，但不应成为所有数值内核的起点

BridgeStan 提供 R 可调用的密度、梯度、参数变换和二阶导数接口。对已用 Stan 的用户，这是可复用的模型入口。另一方面，BlackJAX 和现有 quasi-DEER 实现需要兼容 JAX 的函数。**先在原生 JAX 内比较顺序与并行执行，再做 R/Stan 接口，能减少模型接口与并行机制同时出错的可能。** 这是针对本项目的工程判断，不是已经实测的最优架构。[BridgeStan R API](https://roualdes.us/bridgestan/latest/languages/r.html)、[BlackJAX](https://blackjax-devs.github.io/blackjax/)

| 路线 | 本项目中的用途 | 本轮建议 |
|---|---|---|
| 标准 Stan＋BridgeStan | 连续参数模型入口、独立 CPU 路线、跨实现核验 | 采用；在内核验证后接入 |
| 原生 JAX 目标函数 | 同后端时间并行、自动微分、GPU 实验 | 首条开发与实验路径 |
| BUGS 风格＋NIMBLE | 图结构、局部 Gibbs、离散/连续混合采样 | 当前不做第二入口；研究范围改变时重评 |
| 自定义语言或 Stan 子集编译器 | 一个模型生成多后端 | 延后；仅在重复维护模型成为实际瓶颈时评估 |

NIMBLE 已支持 AD、参数变换和 HMC/NUTS；不能把 BUGS 风格与“无法做梯度”画等号。Stan 的离散潜参数通常需要边缘化；这也不意味着不能建含离散观测的模型。[NIMBLE 手册](https://r-nimble.org/manual/cha-AD.html)、[Stan 离散潜变量](https://mc-stan.org/docs/stan-users-guide/latent-discrete.html)

BridgeStan 接入 JAX 的回调不自动变成 GPU 模型；JAX FFI 可以接 CPU 或 GPU 内核，但需要对应实现及导数/批处理规则。因此首版不应承诺“任意 Stan 文件自动获得 JAX GPU 加速”。[JAX FFI](https://docs.jax.dev/en/latest/ffi.html)

### 2.2 BridgeStan 的 HVP 并非默认自动微分 HVP

官方编译说明和源码显示，默认 Hessian/HVP 使用有限差分；嵌套 AD 需要显式启用 `BRIDGESTAN_AD_HESSIAN`，还受模型所用运算的支持范围约束。模型能力不能只记录 `has_hvp`，还要记录导数来源、阶数、精度、构建选项及成本。[官方说明](https://roualdes.us/bridgestan/latest/getting-started.html#autodiff-hessian-calculations)、[固定提交源码](https://github.com/roualdes/bridgestan/blob/fdd18fdb566416e575feb6e3c6c01195e7d1ad4d/src/model.hpp)

目标密度 HVP 也不是完整 MCMC 转移的导数。接受分支、积分器和随机输入都在转移层。当前 quasi-DEER 上游对硬接受规则使用替代导数参与线性化；它不是把接受核直接改成平滑概率核，也不是普通光滑 Newton 假设自动成立。具体实现见工程审查。

### 2.3 “有公开代码”不等于“包装即可使用”

静态核查 `parallel-mcmc` 的固定提交发现：求解代码含迭代裁剪、非有限值修复、按 dtype 内置的容差；返回轨迹与迭代次数不足以说明原递推已满足。需要增加终止原因、完成长度、真实递推残差、接受分支差异和数值修复记录。**这说明包装需要额外审计，不说明原论文结果错误。** [qdeer.py](https://github.com/lindermanlab/parallel-mcmc/blob/5e5b637b1214580d0be4e495215e0e5ed6eb2688/src/qdeer.py)、[窗口版](https://github.com/lindermanlab/parallel-mcmc/blob/5e5b637b1214580d0be4e495215e0e5ed6eb2688/src/windowed_qdeer.py)

ParallelMH 当前 Julia 核心的刷新函数使用普通循环；另有针对特定实验的 MATLAB `parfor` 代码。当前仓库树未发现许可证文件，尚不能确认可直接派生分发。复现作者实验、依据论文独立实现并行执行器、复制源码做包，应列为不同工作。它不宜被当作现成 R/JAX 并行依赖。[Julia 核心](https://github.com/SebaGraz/ParallelMH/blob/b03ef0f3a46947d0253c75e41cd7d060c6aa1111/src/online_picard.jl)、[MATLAB 例程](https://github.com/SebaGraz/ParallelMH/blob/b03ef0f3a46947d0253c75e41cd7d060c6aa1111/Parallel_Picard_Sec_6_8/ONLINE_PICARD.m)

因此，原方案的分周工期只能作为设想。当前没有兼容性试验、人力投入或独立重实现工作量，不能据此承诺总周期。

### 2.4 相关工作比原评价列出的更接近

原评价正确识别 compareMCMCs、BridgeStan、BlackJAX 和时间并行实现的重叠，但还应加入下列前作：

| 前作 | 与构想的具体重叠 | 对候选贡献的约束 |
|---|---|---|
| [compareMCMCs](https://github.com/nimble-dev/compareMCMCs) | R 中跨引擎运行、计时和指标扩展 | 统一调用本身不新 |
| [PPL Bench](https://github.com/facebookresearch/pplbench) | 多模型、多 PPL 的评价框架 | 不能以“跨软件基准”作首次声明 |
| [Inference Gym](https://github.com/tensorflow/probability/tree/main/spinoffs/inference_gym) | 模型 shape/dtype、变换、密度、后验函数及带 MC 标准误的参考量 | 模型契约和参考量管理已有可复用设计 |
| [posteriordb，AISTATS 2025](https://proceedings.mlr.press/v258/magnusson25a.html) | 模型、数据与参考后验抽样 | 优先复用，逐个核查参考质量 |
| [ParallelMCMC.jl](https://github.com/rsenne/ParallelMCMC.jl) | 时间并行 MALA 与 AbstractMCMC 集成 | “首次把时间并行做成库”不成立 |
| [BayesForge](https://cran.r-universe.dev/BayesForge/doc/manual.html) | R 接 JAX/NumPyro 的建模与推断接口 | R＋GPU 不构成独立差异 |

BayesForge 还已有 2026-08-14 的 v2 预印本，不能只把它列作软件文档。本轮核到作者页与摘要；正文直开受限，**未确认其性能主张**。[预印本](https://www.biorxiv.org/content/10.64898/2026.01.19.700318v2)

DeepStan 的 Stan→生成式 PPL 编译也是直接前作，但现有 Stan/JAX 版本兼容性仍需另测，不能根据论文存在就定为生产依赖。[论文](https://arxiv.org/abs/1810.00873)

### 2.5 运行时核验与离线审计必须区分

Picard 已确认前缀、给定容差的 quasi-DEER 解、有限轮数近似输出，保持的性质不同，不应排成一条“可靠性等级”。建议分别记录：目标/核性质，路径一致性，数值停止条件，以及测试证据。

如果最终用完整顺序重算来确认并行轨迹，则这可以是离线审计；若产品宣称每次返回前自动获得该证书，就必须把重算成本计入运行时间。小迭代差、小残差和“多数接受事件相同”均不等于严格轨迹证明。[Newton 精读卡](../../../../review/cards/zoltowski2025/paper-card.md)、[Picard 精读卡](../../../../review/cards/grazzi2026/paper-card.md)

### 2.6 支持范围应是组合矩阵

`模型提供方式 × 核 × 执行器 × 精度 × 设备` 必须逐项列出“已测试/未测试/不支持”。有 Stan 模型、有 HVP、有 GPU，并不能组合推出任意 Stan 模型支持 GPU quasi-DEER。CPU 并发还需处理 BridgeStan 构建标志、模型生命周期、线程/RNG 所有权及嵌套线程数，不能只暴露一个 `workers` 参数。[并发要求](https://roualdes.us/bridgestan/latest/getting-started.html#enabling-parallel-calls-of-stan-programs)

## 3. 实验协议需要补上的四处统计问题

### 3.1 独立参考后验仍有误差

令算法估计为 A，参考估计为 B，目标为 μ；各自偏差为 b_A、b_B，则直接展开可得

\[
\mathbb E(A-B)^2=\operatorname{MSE}(A)+\operatorname{MSE}(B)
-2b_A b_B-2\operatorname{Cov}(A,B).
\]

即使 B 独立无偏，比较量也等于算法 MSE 加参考方差。若全部重复共享一个参考值，其随机偏移不会靠增加算法重复次数消失。应分开解析真值与参考估计两条路线，报告参考生成过程及不确定性；差异接近参考误差时，应判为证据不足。这个公式是本次代数分析，不是已做的实验。

原方案的最大标准化误差可保留，但要固定函数、尺度与预算网格，并报告不确定性。取最大值通常引入上偏；事后挑最好配置或选择有噪声曲线第一次跨阈值，则可能带来乐观选择。两者不能混称同一种偏差。正式重复数可由独立 pilot 估计后冻结；边看结果边追加重复时需相容的序贯推断。[模拟研究设计指南](https://pmc.ncbi.nlm.nih.gov/articles/PMC6492164/)

### 3.2 墙钟截止规则会影响输出

状态相关的计算时长可导致实时时点观察到的末状态出现长度偏差；这已由 *Anytime Monte Carlo* 分析。它不意味着所有按时间比较都无效，也不能把末状态结论直接套给所有样本均值。[原文 §2](https://www.cambridge.org/core/journals/data-centric-engineering/article/anytime-monte-carlo/3E8ED0F13E0A1E3AF37D09E1515ABFA2)

同核机制实验应先固定转移数 N，完整完成后计时。实时时限实验则预定义何时中断、返回哪些状态、估计量权重、回退与无有效输出规则，独立重复评价整个程序。只保留最快完成的链，或删掉超时后声称无条件达到精度，都不可接受。保留失败率、有效输出的误差和删失时间，必要时预定义失败损失。

### 3.3 自动选择执行器也有条件

若所有候选对同一初值、固定 N 和不可修改随机输入严格返回相同轨迹，选择计算顺序只改变成本。有限容差 quasi-DEER 并不自动满足这一条件；状态相关选择、重抽困难后缀或放宽容差可能改变输出。

首版用独立探测流和正式评估流，完整计入探测/额外编译成本；保留采样随机流与求解器随机流的区分。前缀回退继续使用原随机输入。选择器只在明确的输出标准内比较，留出实验重复完整的“探测—选择—运行”。即使每个备选核分别保持目标，任意状态相关地选核也未必保持目标。

### 3.4 SBC 应当与其他测试互补

原方案对先验预测生成流程的描述正确，但 SBC 不是完整正确性证书。只检验某些参数秩可能漏掉忽略数据等错误；需考虑数据依赖测试量、自相关、秩并列和检验功效。生成器和拟合器共用同一错误也可能互相掩盖。保留解析目标、独立模型实现、接受边界测试和困难几何压力测试。[Stan SBC](https://mc-stan.org/docs/stan-users-guide/simulation-based-calibration.html)、[Modrák 等原文](https://arxiv.org/html/2211.02383v3)

## 4. 结合现有硬件的具体路线

**Mac/CPU 用于开发与正确性测试；5080 台式机作为正式 GPU 实验候选。** JAX 当前支持表将原生 Windows 的 NVIDIA GPU 标为不支持，WSL2 标为实验性支持。NVIDIA 提供 CUDA on WSL 路线，并将 RTX 5080 列为 compute capability 12.0。可先验证 Win11＋WSL2＋Linux 环境中的 GPU 栈；只有实际兼容性或稳定性问题妨碍研究时，再考虑原生 Linux。[JAX 支持表](https://docs.jax.dev/en/latest/installation.html)、[NVIDIA WSL](https://docs.nvidia.com/cuda/wsl-user-guide/index.html)、[GPU 架构表](https://developer.nvidia.com/cuda/gpus)

AMD 是该台式机 CPU 的品牌；GPU 后端依据 NVIDIA 显卡走 CUDA。CPU 型号、RAM、可用显存、驱动与 WSL 配置尚不明确，先不估算可支持的最大窗口或维度。应验证浮点精度与实际吞吐，不能把消费级 5080 等同于原论文 H100 环境。

主机制对照必须在**同一设备、同一后端、同精度**内：例如同一 GPU 上的顺序 MALA 对 quasi-DEER。台式机 CPU 对 GPU、Stan 对 JAX 属于另列的完整工作流比较；Mac 对台式机不能用来归因算法加速。正式实验记录环境版本、线程、链数、窗口、资源占用与缓存条件。

JAX 计时需在结果就绪后结束外层计时，区分冷启动、已有编译缓存和重复调用。分项计时若存在重叠，不直接相加当总墙钟时间；首轮应同时记录外层总耗时。[JAX 基准指南](https://docs.jax.dev/en/latest/benchmarking.html)

## 5. 建议冻结的首个研究问题与验收门槛

主问题建议写成：

> 在固定后验目标、转移核与设备预算下，时间并行何时降低经核验输出的完整成本？这些执行收益在共同后验函数精度下能否保留，又会在何种模型几何、求值成本与资源配置下消失？

其中“经核验”必须注明离线测试还是运行时检查。暂不把自动推荐写进标题。建议将开发拆为以下依赖顺序，替代固定周数：

| 关卡 | 最小工作 | 通过后做什么；未通过如何缩减 |
|---|---|---|
| A 环境与来源 | 固定上游提交，Mac CPU 与 WSL2/GPU 最小求值及精度检查；梳理许可/依赖 | 确认可运行后做内核；暂不可运行时保留 CPU 验证，不能报告 GPU 收益 |
| B 第一对执行方式 | 原生 JAX：顺序 MALA 与窗口 quasi-DEER；解析高斯＋非高斯 logistic；固定实际随机输入 | 能解释残差、分支、停止与完整成本才继续；不稳定时单列近似研究 |
| C 第二条路线 | 按论文验证 RWM＋Online Picard；选择并明确 CPU 或 JAX 实现；验证已确认前缀与回退 | 真实并行和顺序同后端比较通过后纳入；不强求与 B 同时完成 |
| D 模型与 R 入口 | 对应 Stan 实现、坐标/密度/导数核验；R 整批调用、标准结果、能力矩阵 | 从干净环境完整跑通小案例后扩展模型；不先开发解析器 |
| E 正式基准 | 冻结模型族、后验函数、预算、重复及失败协议；加入 NUTS 和资源匹配的多链基线 | 形成可解释的正/负结果后判断论文贡献 |
| F 可选选择器 | 少数配置、独立探测、族级留出，含全部额外成本 | 无稳定净收益就删除自动推荐声明 |

高斯仅用于分离误差和机制，不能作为唯一成功案例。Logistic 至少变化一次真实似然求值成本；不用人为等待代替昂贵似然来证明应用价值。另加一个小型约束变换测试夹具，检查 Jacobian 遗漏能否被发现。进入正式实验后再扩展层次、潜在高斯/时间序列及多峰压力测试；昂贵 ODE 模型等到导数支持明确再纳入。

每个关卡都要保留反例和失败。继续的条件是正确性与成本账本可复核，并出现值得解释的收益边界或稳定负结果；不要求必须观察到加速才准继续。若只有接口包装，没有新的机制证据或可验证的软件增量，则不宜贸然把综述转型为软件论文。

## 6. 什么可以成为论文贡献

三项候选增量应由实验支持：

1. **可复核的比较对象。** 显式记录目标、坐标、核、执行器、随机输入和输出保证，能追溯同核比较中发生了什么变化；不是重新发明模型接口。
2. **执行收益与推断收益之间的实证连接。** 在相同模型和资源下，揭示轨迹加速何时被编译、核验、调参、混合或内存抵消；给出失败和收益边界，避免只报告最大加速比。
3. **可预测性的留出检验。** 只有在基准中确实发现可迁移规律后，才检验简单配置规则是否胜过合理固定配置与简单搜索。窗口化、随机对角、早停或资源取舍本身已是前作内容。

应同时保留两组主要结果：固定核/固定 N 的执行成本，以及共同推断任务的完整流程误差与成本。基线使用同后端编译顺序实现，不能只拿 R 解释器循环作对照。若主张优于现代多链推断，正式研究需加入经过验证的现代多链方案；阶段 B 不必一次完成全部基线。
