术语约定：MCMC 为马尔可夫链蒙特卡洛，RWM 为随机游走 Metropolis，MALA 为 Metropolis 校正 Langevin 算法，HMC 为 Hamiltonian Monte Carlo，NUTS 为无折返采样器。SBC 指基于模拟的校准，MSE 指均方误差，MCSE 指 Monte Carlo 标准误；AD 为自动微分，JVP/HVP 分别为 Jacobian/Hessian 与向量的乘积。dtype 表示数值类型，fp32/fp64 表示 32/64 位浮点，OOM 表示内存不足；WSL2 为 Windows Subsystem for Linux 2。WP 表示开发工作包。

## 1 研究问题与候选贡献

核心问题是：在固定后验目标、转移核与设备预算下，时间并行何时降低指定轨迹的执行成本；这种收益能否保留到共同后验函数误差下的完整推断过程？

| 编号 | 可检验问题 | 所需证据与可接受的否定结果 |
|---|---|---|
| Q1 | 相同坐标、核参数、随机输入和轨迹长度下，时间并行何时有净执行收益？ | 同后端、同设备配对实验；允许测得全区间无净收益 |
| Q2 | 数值容差、接受分支、窗口及失败处理会如何改变轨迹差异和成本？ | 残差、路径、接受事件、失败与回退记录；允许执行器不能满足预设输出标准 |
| Q3 | Q1 的收益能否转化为共同推断精度优势；将资源改分给更多链后结论是否改变？ | 独立重复、参考误差、强基线及全流程成本；允许执行更快但推断无优势 |
| Q4 可选 | 简单配置规则在计入探测和额外编译后，能否在留出模型族上产生收益？ | 重复完整选择流程；若不能胜过合理固定配置/简单搜索，删除自动推荐声明 |

候选贡献由 Q1–Q3 的新证据及可复核实现构成。compareMCMCs、PPL Bench、Inference Gym 和 posteriordb 已提供跨引擎比较、模型契约或参考后验等能力；窗口、随机 Jacobian 近似和早停也已有时间并行前作。因此不以“首次统一接口”“首次比较并行轴”或“首次实现窗口化”作为创新主张。贡献成立与否取决于最终结果能否解释新的收益/失效边界，或形成有实际价值的验证机制。[既有证据表](../02_evidence_table.md)

## 2 首版范围与模型语言

使用标准 Stan，保留现有语义、约束变换和生态；通过 BridgeStan 建立 CPU 路径。采用原生 JAX 目标函数验证时间并行机制，首批仅提供已核对的基准模型，不承诺将任意 Stan 自动翻译为 GPU 模型。NIMBLE 的 AD/HMC 能力真实存在；当前不选它作为另一入口，原因是研究重点为连续目标的时间并行，而非语法优劣。[BridgeStan API](https://roualdes.us/bridgestan/latest/languages/r.html)、[NIMBLE AD](https://r-nimble.org/manual/cha-AD.html)

最小版包含：JAX 上顺序 MALA/窗口 quasi-DEER，RWM/Online Picard；BridgeStan CPU 顺序 RWM/MALA；成熟 NUTS 的外部基线适配；R 批量调用、结果分析及实验日志。明确不承诺离散潜参数通用采样、动态 NUTS 时间并行、通用模型翻译、多机子后验合并或自动算法推荐。离散观测不受上述离散潜参数限制。

| 模型提供方式 | 核与执行方式 | 版本位置与条件 | 当前状态 |
|---|---|---|---|
| 原生 JAX | MALA 顺序、窗口 quasi-DEER | 第一条原型路径，CPU 正确性、GPU 性能 | 计划，未实现 |
| 原生 JAX | RWM 顺序、Online Picard | 第二条原型路径，按论文独立实现并核验 | 计划，未实现 |
| BridgeStan CPU | RWM/MALA 顺序 | 最小 R 包的 Stan 入口与参考执行 | 计划，未实现 |
| BridgeStan CPU | RWM＋Online Picard | 有条件扩展；需要 C/C++ 批量并发实现和净收益验证 | 未纳入最小版必达范围 |
| Stan/CmdStan、原生 JAX | 经过合理调参的 NUTS | 外部基线；同后端机制实验与跨软件比较分列 | 计划，未接入 |
| 任意 Stan 输入 | 原生 JAX GPU quasi-DEER | 不存在默认自动映射 | 首版不支持 |

表中“最小版”是开发目标，不是现有产品说明。每种组合最终还按 dtype、设备和测试模型列出已测试/未测试/不支持。若 Online Picard 暂时无法完成，先交付内部 MALA 原型，不能把两条路线的正式最小版标为完成。

## 3 架构与接口责任

| 层 | 责任 | 必须保留的信息 |
|---|---|---|
| 目标层 | 共同无约束坐标下的密度、变换与后验函数 | 目标/数据/坐标标识，参数顺序，Jacobian，构造随机性 |
| 转移核层 | 提议、接受、预条件和递推语义 | 核版本、步长定义、完整状态、前向规则、实际采样随机输入 |
| 执行层 | 顺序、Picard 或 quasi-DEER 的计算与停止 | 线性化规则、求解器随机输入、窗口、容差、迭代、残差 |
| 调度与实验层 | 资源、计时、重复、失败与配置管理 | 设备/线程、内存、缓存、计时边界、任务与重复 ID |
| R 与分析层 | 整批调用、标准抽样对象、诊断与结果图表 | 估计量、MCSE、参考误差、运行状态和可追溯记录 |

无约束坐标记为 q，原参数为 θ=T(q)，密度定义为 log p(y,T(q))＋log|det J_T(q)|。共同目标允许密度相差参数无关常数；同核比较还要求坐标、参数顺序、预条件、提议尺度定义和接受规则一致。中心化/非中心化作为不同坐标表示记录，不把差异归因于执行器。

导数能力记录 analytic/autodiff/finite_difference、导数阶数、构建选项与支持限制。BridgeStan 默认 Hessian/HVP 的有限差分不能视为原生 JAX JVP；完整转移的导数或替代导数属于执行契约，不能由目标 HVP 的存在推断支持。[BridgeStan 二阶导数说明](https://roualdes.us/bridgestan/latest/getting-started.html#autodiff-hessian-calculations)

R 每次提交整段采样任务或批量求值，不在每一步往返调用 Python。CPU 高频路径由编译代码负责；进程 worker 在各自进程创建模型，线程路径固定 BridgeStan 构建条件并独立管理可变 RNG/缓冲。统一限制外层 workers、BLAS 和 Stan 内部线程，避免嵌套超额订阅。[BridgeStan 并发说明](https://roualdes.us/bridgestan/latest/getting-started.html#enabling-parallel-calls-of-stan-programs)

拟议接口保持五类操作：建立模型、查询能力、运行采样、执行核验、运行基准。API 名称和对象结构在内核关卡通过后冻结，避免先固定不适合上游行为的抽象。未知组合必须报出能力缺口，不静默换核或改数值精度。

## 4 随机输入和输出契约

固定整数 seed 不足以构成同路径实验。配对核验使用共同的提议噪声、接受均匀数/对数均匀数、动量等实际数组；小型测试保存数组与散列，长实验采用可重放的分块规则和独立校验，不要求全部噪声同时常驻显存。记录随机数算法、dtype、链/时间索引和生成成本。

独立管理采样、求解器近似 Jacobian、配置探测、模型/数据生成与 generated quantities 的随机输入。模型实例化若含随机 transformed-data 操作，首版禁用或显式固定并纳入目标标识。选择器不得挑选更快的采样噪声带作为正式样本。

每次输出分别记录三类信息，而非单一“精确”等级：

- 理论性质：预定转移核及其已知保证、适用条件和文献来源。
- 轨迹/数值证据：前缀确认、离线顺序比对、数值容差、真实递推残差、接受分支差、裁剪和非有限值事件。
- 运行状态：完成、超时、OOM、非有限求值、求解轮数耗尽或其他错误；另记输出是否满足预声明任务标准。

Picard 仅输出按其算法规则确认的前缀。quasi-DEER 首版按数值求解输出管理：收敛判定除迭代差外记录原递推残差，有限容差不自动获得严格路径确认。替代导数和中间迭代稳定化分别记录，不直接把中间裁剪认定为改变最终目标，也不默许将 NaN 修复后的轨迹作为成功样本。终止原因和修复事件必须可追溯。[上游核查](../qa_logs/feasibility-review.md)

默认不将未满足任务标准的结果转换成正常 fit。探索性近似输出采用显式模式，保留其证据类别。Picard 失败可从已确认前缀按原随机输入顺序继续；quasi-DEER 不能从仅因容差而被称为“确认”的位置继续，应回到初值或独立确认的检查点重算。全部失败、重算和回退成本入账，不能重抽困难后缀。

完整顺序重算可用于离线开发审计；若发布功能宣称每次返回前提供该核验，则必须计入其运行时成本。两种报告分列，不能排除重算成本却宣传每次运行均被自动认证。

## 5 硬件与环境策略

已确认硬件为 Mac/CPU，以及 AMD CPU＋RTX 5080、Windows 11 台式机。Mac 用于开发与 CPU 正确性；台式机先在 WSL2 Linux 环境中验证 JAX GPU，再固定正式基准环境。JAX 当前官方表中，原生 Windows 的 NVIDIA GPU 不支持，WSL2 为实验性支持；这是一条待实测路线。[JAX 安装表](https://docs.jax.dev/en/latest/installation.html)、[CUDA on WSL](https://docs.nvidia.com/cuda/wsl-user-guide/index.html)

WP00 收集 CPU 型号/核心数、RAM、GPU/可用显存、驱动、WSL/内核、R/Python/JAX/编译器版本和电源/设备占用条件。AMD CPU 不改变 NVIDIA GPU 使用 CUDA 的选择。不能将 5080 与原论文 H100 性能直接类比，也不预设 fp64 开销可忽略。

先使用 fp64 完成小型正确性与主机制比较；fp32 是分列的数值精度因素，不能混入主加速比。若 fp64 无性能收益仍保留结果，再按同精度协议研究 fp32。主比较在同一设备、同后端进行；CPU/GPU、Stan/JAX 和 Mac/台式机对照属于另列的完整软件/硬件工作流比较。

上游固定提交与依赖版本写入环境清单，不盲目升级到 latest。研究代码依赖与最小核心依赖分开，先确认 JAX/TFP 等实际组合。WSL2 若持续不稳定，再评估原生 Linux；这不是本轮安装或修改系统的操作指令。

## 6 首批模型和小规模探测协议

首批为两模型族、四个任务，外加约束测试夹具。以下数字是预实验设计，不是已测结果；用于控制初期工作量，正式实验另行冻结。

| ID | 目标与规模 | 要检验的机制 |
|---|---|---|
| G1 | 8 维标准高斯 | 解析函数真值、基础递推与编译/调度开销 |
| G2 | 64 维旋转高斯，协方差条件数 100 | 相关性、尺度与近似 Jacobian；旋转矩阵和谱固定保存 |
| L1 | Bayesian logistic，8 个连续系数、256 条观测，固定正常数方差的正态先验 | 非高斯目标、有限似然成本 |
| L2 | 与 L1 同族，8 个系数、4096 条观测 | 真实似然求值量增加后的变化；不使用人为等待模拟成本 |
| T1 | 单一正参数的可解析变换夹具 | 变换、Jacobian、参数顺序与边界附近测试；不计作性能模型族 |

Logistic 的首版具体生成规则：含一个截距与七个标准化正态协变量；系数先验独立 N(0,2.5²)，生成系数和独立数据随机流固定并保存；响应按 logit 链接生成。L1/L2 的样本量属于同一族的变化，不充当训练/测试独立模型族。G2 的旋转由固定随机矩阵 QR 构造，正交矩阵、谱、最终协方差与数据一同归档。

G1/G2 可评价均值、二阶矩和固定阈值尾部概率；Logistic 第一关主要核验密度/导数、轨迹与成本，不将其未知期望当解析真值。共同精度实验必须先满足第 8 节参考协议。

初始执行网格为转移长度 N∈{256,2048}、窗口 W∈{16,64,256} 且 W≤N；先 1 链，再在选定任务做 4 链资源竞争探测。先以 3 条固定独立随机输入带检查每条路线，再只对通过输出标准的组合测计时；失败保留在总任务表。三次不是正式统计结论所需重复数。

MALA/RWM 的步长、预条件和初值在独立 pilot 中选定，记录上游尺度参数到数学递推的映射。先用常规、固定参数核完成路径验证，再接预热适配。配对执行方式共用同一冻结参数与实际随机输入，不允许各自重新调参。阶段内先跑 G1，再 G2/L1，最后 L2，不做全部模型、链数、窗口、精度的完整全因子扫描。

## 7 正确性验证与接受准则

| 层次 | 检查对象 | 接受或失败规则 |
|---|---|---|
| V1 目标 | 共同坐标密度差、梯度、约束映射、导数算子 | 典型/尾部/边界附近点，独立解析或手工实现；容差及尺度在测试前登记 |
| V2 核 | 提议与接受概率、状态顺序和拒绝自环 | 与独立小型顺序参考比对；核参数/步长定义不一致即失败 |
| V3 执行 | 完整小轨迹、接受序列、残差、终止和前缀/回退 | 逐比特、给定容差内一致、理论等价分开；分支不一致不能标为同路径 |
| V4 统计 | 解析函数误差、有限 SBC 和压力目标 | 独立重复并给不确定性；测试通过不替代一般正确性证明 |
| V5 软件 | 能力拒绝、资源限制、可重放失败、完整日志 | 不支持组合明确失败；人为触发 OOM 采用安全受控资源限制，不耗尽整机 |

容差先根据解析模型、dtype 和函数尺度确定；将相对/绝对误差及阈值写入测试规格，不为追求通过或加速事后放宽。跨后端对数密度以相对参考点差值比较；使用不同变换时先转换坐标与相应导数。数值有限差分校验需检查步长敏感性，不能把单个差分步长当绝对真值。

错误注入至少包含漏 Jacobian、尺度变换错误和接受判定错误，确认独立测试能识别。SBC 使用先验预测生成流程，包含参数与数据依赖测试量，处理自相关与秩并列；记录所有生成数据和拟合失败。先验预测整体校准、固定数据集可靠性和全实现正确性分别表述。[SBC 方法依据](https://arxiv.org/html/2211.02383v3)

## 8 正式实验协议

### 8.1 两类主实验分开

E1 为同核执行实验：固定目标、坐标、精度、初始化、核参数、实际随机输入、转移数和设备预算，只改变执行器/窗口。顺序对照使用同后端编译实现，包含拒绝产生的自环。报告净时间比、调用数、迭代数、峰值内存、路径证据、失败/回退及其不确定性。严格同路径条件不满足的 quasi-DEER 配置进入数值差异结果，不混入已确认路径速度排名。

E2 为完整推断实验：固定原参数尺度的函数集合和资源约束，允许各核合理调参，计入全部推断开销。至少包括成熟 NUTS、同设备资源下的多链方案；若主张与现代多链方法竞争，再加入经过复现的 MEADS 或 LAPS 等相关基线。不同后端结果称完整软件工作流比较。E1 提速不直接推出 E2 优势。

### 8.2 误差、参考和不确定性

预声明函数集合 F、尺度 s_f、精度参数 ε 和预算网格，以 max_f MSE(估计量_f)/s_f²≤ε² 定义共同精度目标；ε 对应标准化均方根误差尺度。函数需要相应矩存在，重尾压力目标优先用有界函数。解析目标使用真实期望 μ_f；非解析目标使用独立参考并报告其生成方法、误差估计和探索风险。

每函数评价独立重复下的标准化平方误差；整体采用预声明的最大值，并同时保留每函数曲线。令 A 为算法估计、B 为参考估计，则 E[(A−B)²]＝MSE(A)＋MSE(B)−2b_A b_B−2Cov(A,B)。独立无偏参考仍带来参考方差，不能把与参考的平方差直接命名为真实 MSE，也不能无条件扣除一个方差估计后这样命名。

重复数由独立 pilot 的误差方差和资源上限设计，在正式运行前冻结。计划精度目标为标准化 MSE 的 MCSE 相对目标阈值 ε² 足够小，初始设计比例为 0.1；该比例是研究设计值，若预算无法满足则在冻结前修改并说明。正式运行不根据有利结果随意加样；若确需边看边追加，改用预声明的序贯方法并保留方案变更。

独立重复是主要不确定性单位；有公共随机输入的配对比较在分析中保留配对。共用参考造成的共同不确定性单独传播，不把链内样本数当独立实验重复数。报告曲线、区间和未判定区域；不能从多个有噪声预算点事后挑一次跨阈值作为精确达标时间。

### 8.3 墙钟预算与失败

E1 默认固定 N，完成后计时；达到资源上限的运行保留为未完成，不当作恰在上限时完成。E2 首先采用固定采样计划对应的成本—误差曲线，避免把不可观测真实 MSE 伪装成在线停止规则。

若另做硬墙钟截止实验，必须先登记中断点、最终返回哪些已确认样本、权重、回退和没有有效估计时的状态；用独立重复评价整个程序。状态相关运行时可能改变实时时点观察的分布，不能只取最快完成的链。报告失败率、有效输出上的条件误差及未完成成本；不删除失败后声称无条件达标。需要单一效用时，先定义失败损失。[Anytime Monte Carlo](https://www.cambridge.org/core/journals/data-centric-engineering/article/anytime-monte-carlo/3E8ED0F13E0A1E3AF37D09E1515ABFA2)

### 8.4 时间与资源口径

外层墙钟计时在设备结果就绪后结束，记录冷启动、已有编译缓存的运行和多次调用的摊销情境。分解编译、探测、预热、采样、核验、传输/输出和诊断；有重叠阶段不机械相加。一次性安装、人工作业和开发调试另外报告，不混入单次推断时间。[JAX 计时依据](https://docs.jax.dev/en/latest/benchmarking.html)

固定总设备预算的资源分配，与增加 CPU 核心/GPU 的扩展实验分别报告。本项目先做单台式机单 GPU，不能由此声称多 GPU 或集群扩展性。记录 dtype、线程、链数、窗口、内存、并发占用、缓存策略；测量次序按预先随机化顺序执行，排除明确的外部干扰须依据预声明规则且留痕。

### 8.5 正式模型库与协议冻结

核心候选族包括高斯、回归、层次模型及潜在高斯/时间序列；另设已知模式结构的多峰压力任务。昂贵 ODE/其他似然仅在导数与验证条件具备时加入。优先复用 posteriordb/Inference Gym，逐个检查模型语义、坐标和参考质量，不以总模型数代替覆盖论证。[posteriordb 正式论文](https://proceedings.mlr.press/v258/magnusson25a.html)、[Inference Gym](https://github.com/tensorflow/probability/tree/main/spinoffs/inference_gym)

WP06 在开发性探测后产生 `protocol-v1`：列明实际模型/数据版本、函数/尺度/阈值、初始化、调参预算、基线、候选配置、随机流、重复数、资源上限、计时与失败/不确定性方法。冻结后结果不再用于挑选有利模型；修改生成新版本，原结果保留。模型数量若不足以支持族级泛化，就缩小结论，不把同族中心化/非中心化或不同 seed 当成独立族。

若预期开展 WP08，在 WP06 即预留并封存选择器测试族的结果，配置规则和分析方法冻结后才解封并记录访问。若 WP07 全部结果已经用于认识机制或制定规则，这些模型族均属于开发资料；WP08 必须另设未参与规则制定的新测试族，不能仅换随机种子重新命名为留出测试。无法保留独立测试族时，仅报告探索性选择结果，不声明泛化验证。

## 11 风险处置与范围控制

| 风险 | 触发信号 | 处理 |
|---|---|---|
| WSL/JAX 不稳定 | 最小计算或依赖组合不能重现 | 固定版本排查；CPU 验证继续，必要时评估原生 Linux |
| 数值求解不能满足标准 | 残差、分支或完成长度不符合规格 | 保留失败；严格模式回退，近似模式单列，不静默放宽标准 |
| 没有净提速 | 编译、核验或资源竞争抵消执行收益 | 报告负例/边界；限制推荐范围，不挑最快一次 |
| 参考精度不足 | 算法差异接近参考误差或探索不一致 | 增强独立参考或降为未判定，不宣称精确排序 |
| 工作量超限 | 依赖/模型维护挤占机制实验 | 先删选择器、HMC、ODE 与第二模型语言，保留核心两路线验证 |
| 选择器无泛化收益 | 留出族不优于合理固定配置/简单搜索 | 不纳入主贡献；平台和基准独立交付 |

研究阶段改变支持范围时，更新能力矩阵、工作包和论文声明。新语言、完整动态 NUTS 时间并行和多机扩展需要独立立项，不从小功能需求逐步隐含引入。
