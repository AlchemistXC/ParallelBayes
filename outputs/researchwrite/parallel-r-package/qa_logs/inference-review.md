# R 包研究方案：实验统计与贡献专项审查

日期：2026-10-03。对象：用户粘贴的 ChatGPT 方案；仅审核，不实现软件、不修改现有综述。本记录是 AI 专项审查，不代表真人专家或投稿决定。通过官方文档、原始论文和现有精读卡核实关键论点；未运行拟议软件或复现实验。

## 判断与审查口径

总体判断：支持“平台—基准—有限配置选择”的研究顺序。原方案对同核执行比较、共同精度比较、编译开销、失败保留和模型族留出的区分基本正确。尚不能直接冻结为正式实验协议：参考误差、实时中断、探测选择和有限容差输出四处仍可能改变被比较的统计对象。

优先级：P0＝正式结论成立前必须解决；P1＝正式协议中应明确；P2＝后续增强。标签“证据”表示有核实来源；“推断”表示本次推导或设计判断；“待测”表示需实际实现或试验才能回答。P0 不表示整个项目不可行。

## P0-1：独立参考样本仍不是后验真值

**位置：**第五部分第三层的经验误差公式；“独立高精度参考”的解释。

**[推断：直接代数]** 令算法估计为 A、参考估计为 B、真值为 μ，偏差分别为 b_A、b_B。则

\[
\mathbb E(A-B)^2=\operatorname{MSE}(A)+\operatorname{MSE}(B)-2b_A b_B-2\operatorname{Cov}(A,B).
\]

只有独立且参考无偏时，右侧才简化成算法 MSE 加参考方差。参考与被评算法独立不会消除参考偏差；多个算法重复共同使用一个 B 时，增加 R 也不会消除这个参考值的随机偏移。反而所有算法误差会共享这一不确定性。若用待评估样本构造参考，协方差还可能制造表面优势。

**修订：**将式中 `μ_f*` 拆为“解析真值”和“参考估计”两条分析路径。后者报告参考生成算法、独立链/重复、误差评估与可能的未探索模式；性能差异接近参考不确定性时给“不足以区分”。不要不加条件地减去一个估计方差后称为真实 MSE。首轮核心实验优先使用解析函数真值；复杂后验的结论降为含参照不确定性的误差比较。

**[证据]** posteriorDB 提供模型、数据、参考实现和参考后验样本，用于准确性/速度测试；“参考样本”并不等于已知所有函数真值：[官方仓库 README](https://github.com/stan-dev/posteriordb)。本项目既有主稿 `manuscript/中文综述.tex` 第 383、389 行已承认参照误差，但尚未给此分解。

## P0-2：截止墙钟时间取输出是一个统计规则，不只是计时规则

**位置：**共同预算 t、失败/超时、末状态与短链结果汇总。

**[证据]** Murray、Singh、Lee (2021), *Anytime Monte Carlo* §2、Corollary 2 给出：在其计算时长模型和稳态条件下，按实时时间观察当前状态的分布满足

\[
\alpha(dx)=\frac{\mathbb E[H\mid x]}{\mathbb E[H]}\pi(dx).
\]

因此依赖状态的计算时长可能造成长度偏差。原文明确区分最后状态与全部已完成状态的平均；后者的额外偏差可随预算增长减小，不能把最后状态结论无条件套到所有平均估计。[原文 §1–2](https://www.cambridge.org/core/journals/data-centric-engineering/article/anytime-monte-carlo/3E8ED0F13E0A1E3AF37D09E1515ABFA2)，DOI 10.1017/dce.2021.6。

**[推断]** 若完成事件 C 依赖轨迹，只保留完成链得到的是条件于 C 的结果；一般有 `E[f(X)|C] != E[f(X)]`。这与仅报告成功运行平均时间的幸存者偏差相关，但不是同一命题。不能由“每条链使用保持目标的核”推出“取最快完成的若干链仍代表目标”。

**修订：**同核机制实验预先固定转移数 N，包含拒绝自环，完整完成后计时。端到端实时时间实验仍然可做，但预定义中断位置、返回哪些已确认状态、平均权重、未完成输出、回退和超时；独立重复评价这个完整程序的实际 MSE。不能把预算末状态自动标为精确后验样本。无法返回有效估计的运行记失败，报告成功率及成功条件下误差；不能对删掉失败后的 MSE 声称无条件精度。硬上限导致的未完成运行属于右删失成本，不能当作“在上限时完成”。

## P0-3：自动选择执行器的安全条件比“先不选核”更具体

**位置：**第七部分短时探测、顺序/窗口选择和随机输入复用。

**[推断]** 如果所有候选对同一固定初值、不可修改的随机输入带、固定 N，严格返回同一轨迹，那么依据这条轨迹的性质选择计算顺序不会改变最终轨迹分布；它只改变成本。这是很有价值的收窄。但有限容差 quasi-DEER 不自动属于这个保证集合。若窗口、容差、候选核或重启规则改变输出，则“每个备选核各自保持 π”也不足以保证状态相关选择保持 π。简单反例：二状态均匀目标上，恒等核和翻转核各自保持目标；在状态 0 选恒等、状态 1 选翻转，会把所有概率送到 0。

**修订：**把随机输入拆成采样随机输入、数值求解器内部随机输入（如随机 Jacobian 近似）、配置探测随机输入，记录它们的用途和复用规则。首版配置选择使用独立探测流与独立正式评估流，所有探测成本入账；不能挑中速度有利的噪声带后把它作为正常推断输出。精确执行器保留整个随机输入带，回退从已确认位置继续，不能重抽困难后缀。近似执行器按预定容差等级分别评价，不允许选择器悄悄放宽容差。正式留出实验重复完整“探测→选择→运行”流程，不能只重计选中的内核。

**[证据]** 已研读 Newton 论文：`review/cards/zoltowski2025/paper-card.md` §§7、10–11，原文 PDF p.4–5、p.9、Appendix A p.23；窗口、随机对角与早停均已有前作，早停仅有特定经验支持。[论文](https://proceedings.nips.cc/paper_files/paper/2025/hash/202886ee1c9ca735cb5bff3a00a69883-Abstract-Conference.html)。Picard 已确认前缀依据 `review/cards/grazzi2026/paper-card.md` §§7–11，原文 Algorithm 2、§5：[论文](https://doi.org/10.1093/biomet/asag022)。

## P1-4：最大函数误差与“首次达到阈值”的不确定性应分开

**位置：**第五部分经验最大标准化 MSE；第六部分按不确定性增加重复。

**[推断]** 当每个函数误差估计无偏时，取最大值通常有上偏：`E[max_f Ehat_f] >= max_f E[Ehat_f]`；不能把它误说为乐观偏差。相反，事后挑最好配置、最有利函数集合或从有噪声的多预算曲线上选择首次越阈值，可产生乐观选择。维度增加意味着最大值覆盖的函数数量可能增加，因此“高维更慢”的部分现象也可能来自更严格任务。用估计的尺度分母还会再引入随机性。

**修订：**预注册主函数、尺度来源、预算网格、最大值或均值聚合方式；均值/二阶矩/模式质量分别报告。输出每函数曲线和整体曲线的不确定性，不只给单个首次达标点。阈值相邻预算点证据不足时报告一个达标区间或“未判定”。重复数可以通过独立 pilot 估计所需精度后冻结；若正式运行边看置信区间边追加重复，应使用相容的序贯推断，不要沿用普通固定样本区间声称名义覆盖。

**[证据]** Morris、White、Crowther (2019) 强调先定义目标、生成机制、估计量、方法及性能指标，并报告有限重复造成的 Monte Carlo 不确定性；具体最大值和选择推论是本次分析。[原文 §3–5](https://pmc.ncbi.nlm.nih.gov/articles/PMC6492164/)，DOI 10.1002/sim.8086。

## P1-5：SBC 需要测试量与相关性设计，不能作为万能通过证

**位置：**第五部分第一层，统计正确性。

**[证据]** Stan 官方 SBC 文档要求先从先验模拟参数、再生成数据；常用秩均匀性检验依赖近似独立的后验抽样，应处理 MCMC 自相关。[官方文档](https://mc-stan.org/docs/stan-users-guide/simulation-based-calibration.html)。Modrák 等的原始研究表明，仅使用不依赖数据的参数测试量，可漏掉完全忽略数据而返回先验等错误；引入如联合对数似然的数据依赖测试量可增强敏感性。[原文 §3.3–3.4、§4.3](https://arxiv.org/html/2211.02383v3)。

**修订：**选择参数、预测或联合函数及数据依赖测试量；明确自相关处理、秩并列处理和有限重复的检验功效。解析目标、独立密度/梯度比对、针对接受边界的轨迹检查与 SBC 互补。生成器与拟合器共享同一个建模错误可能一起通过，故保留独立的解析或手工实现。SBC 在先验预测分布上校准不保证每个现实数据集都可靠；困难几何压力测试仍需单列。先验非常宽时，SBC 成本和失败本身也需记录，不能只保留好拟合的数据集。

## P1-6：同一后验不等于同一核；数值近似轨迹也不等于已确认轨迹

**位置：**Stan/JAX 密度一致性、层次模型中心化/非中心化及“两组成对执行方式”。

**[推断]** 统一原参数后验是端到端比较的底线；同核比较还要求统一无约束坐标、变换、状态顺序、步长、预条件、提议密度和随机数语义。非线性重参数化之后使用同名 MALA/RWM，通常已经改变原参数尺度上的核。中心化与非中心化可作为模型表示因素，但不能把其效率差异归于执行器。两个后端的相同整数 seed 也不能替代同一噪声数组和均匀随机变量。

**修订：**记录 `target_id`、`coordinate_id`、`kernel_id`、`executor_id`、数值精度和 RNG 规则。给每个方法—执行器组合逐项列出支持范围；不是所有 log-density+gradient 模型都适配任意执行器。quasi-DEER 先以“同一指定递推的数值求解”标识，报告接受分支差、路径残差和离线顺序核验；仅小残差不能授予精确证书。完整顺序核验可作为离线审计，不应把它的额外成本藏在性能实验之外同时又声称运行时自动认证。

**[证据]** 现有主稿 `manuscript/中文综述.tex` 第 117–125、249–279 行；精读卡的相应原文定位见 P0-3。Stan 约束映射及 Jacobian 的官方语义：[Reference Manual](https://mc-stan.org/docs/reference-manual/transforms.html)。

## P1-7：发表增量要落在可被推翻的机制结论，而非方法数量

**位置：**第一部分三层贡献；首版方法与系统基准。

**[证据]** Zoltowski 等已比较 MALA 的链数/链长、HMC 两个并行轴、随机对角与早停，并报告速度反转/内存限制（原文 Fig.3–6；精读卡 §10）。Grazzi 和 Zanella 已含回归、ODE 及实际并行开销（原文 §6；精读卡 §10）。LAPS 已将冷启动、多链和强基线纳入比较（原文 Tables 1–2；`review/cards/robnik2026/paper-card.md` §§7、10）。因此“系统比较是否值得并行”“窗口越大内存越大”本身不够新。

**[推断]** 最有希望的增量是：跨同一模型语义、同后端和完整成本，测出可复核的收益/失败边界；解释哪些模型特征或资源约束造成结论反转；检验这些判断能否跨模型族预测。软件协议、验证机制与负结果是支撑此证据的交付，而非自动产生论文新意。能否形成足够发表增量仍待结果，不能预先保证。

**修订：**至少保留同后端顺序实现、同总设备预算的多链资源分配、合理调参的成熟梯度基线。主研究若声称与现代多链竞争，应加入一个已验证可用的现代多链方案；不必在 stage 0 一次完成所有基线。区别“同核固定 N 执行速度”与“不同核共同精度完整流程”两张主结果表。不把慢的 R 解释器循环作为编译并行方法唯一顺序对照，不把未调参或错误参数化的 NUTS 当成主要胜出证据。

## P2-8：失败率、成本与精度应保留多个轴

**[推断]** 单一平均时间或成功条件下 ESS/s 会掩盖 OOM、发散、接受分支失配与尾部遗漏。失败是结果类别，不能任意赋一个巨大 MSE 与正常运行混平均，也不能删除。

**修订：**对每个预声明任务输出成功/失败/预算内未判定三态、独立重复数、全流程成本分解、峰值内存，以及在有效输出上的误差分布；若需要单一决策分数，预先定义失败损失。冷/热启动都记录；随机运行次序、缓存条件和设备占用作为实验控制。MSE 比较需要存在相应矩；重尾目标改用有界函数或明确矩条件。

## 建议冻结的最小可证伪问题

**Q1（首个核心问题）：**在固定模型坐标、核参数、随机输入、轨迹长度和同一设备预算下，Online Picard 与顺序执行何时有净时间收益；这种收益能否由目标求值成本、窗口推进率和并行开销共同解释？将便宜解析高斯与一个真实较昂贵、密度可独立核验的目标配对。应允许结果为“给定设备/模型范围无收益”。

**Q2（第二条路线，先做可行性关卡）：**窗口化 quasi-DEER MALA 在明确数值精度/容差下是否稳定恢复指定轨迹，并在计入编译与内存后产生收益？若接受事件差异或求解失败无法管理，保留为近似执行研究，不与已确认 Picard 共用精确标签。

**Q3（正式跨模型研究）：**同核收益能否转化为预定后验函数上的共同精度收益；当同设备资源改分配给更多链时，收益区间是否改变？这需要独立的端到端实验，不能由 Q1/Q2 推出。

自动选择器暂定为可删除的第二阶段目标。其成功标准是：含全部探测和额外编译成本，在留出模型族上相对合理固定配置及简单搜索有可重复的净收益；失败应导致缩小声明，而不是扩大搜索直到找到有利设置。

## Stage 0 验收，不绑定固定工期

1. **算法来源与输出契约：**锁定上游版本，写出递推、随机输入、接受规则、返回状态与失败状态；识别伪代码/代码差异。先完成一对执行方式再进入第二对，避免 R API 提前固定错误抽象。
2. **数学目标核验：**两目标至少一个有解析期望；比较共同坐标下的相对 log density 与所需导数，覆盖典型点、尾部及变换边界。故意遗漏 Jacobian/修改接受符号的错误注入必须能被测试发现。
3. **轨迹核验：**固定实际噪声带和 N；Picard 检查全部输出和接受序列；quasi-DEER 记录误差随容差变化、分支差与失败。浮点逐比特相同、给定容差内一致、数学轨迹等价分别标识。
4. **统计目标核验：**解析函数均值/二阶矩/有界尾部事件按独立重复给误差及 Monte Carlo 不确定性；对有生成器的简单模型做小型 SBC 验证管道，不把小型通过当作充分证明。
5. **真实成本可解释：**同步设备后计时，记录编译、求值次数、确认步数/迭代数、数据传输、峰值内存和回退；串行对照使用同后端，不用人为 `sleep` 代替昂贵似然作为应用收益证据。
6. **失败可复现：**至少测试一个故意触发预算不足或求解失败的配置，保留输入/噪声/日志，从确认前缀回退不改变随机输入；不依赖删除失败链得到好结果。
7. **继续条件：**正确性和成本账本能复核，且观察到值得解释的收益边界或稳定负结果，才扩展模型族和包装 R API。仅看到编译后一次最快时间，或两个后端目标尚未对齐，不通过此关卡。

## 核心修订建议与评分

最重要的单项修订：**把“共同精度—总时间”从概念目标写成明确的输出/参考/失败协议，再实施性能比较。** 当前计划中最可能制造虚假优势的不是没有某种语言特性，而是比较对象随参考误差、超时或选择规则而变化。
