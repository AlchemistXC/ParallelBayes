\begin{abstract}
时间并行MCMC同时求解多个采样位置，尝试缩短单条轨迹的计算时间，其收益取决于并行计算能否抵消额外求值和同步。本文介绍带R接口的研究软件ParallelBayes，将目标函数、转移核和执行器分开实现，并在固定实际随机输入下核对路径、接受事件和成本。在所测M4 CPU配置中，两类时间执行器均未取得组中位缓存执行加速；在独立的Windows实验中，RTX 5080上Picard的组中位缓存速度比为1.10--5.23，quasi-DEER仍较慢。部分Picard收益伴随全部拒绝，说明较短执行时间可与无效探索同时出现。已有机制对照显示，窗口宽度带来的批处理机会会被重复求值和较慢的前缀推进抵消。本文据此区分同核执行成本与后验函数误差；采用独立调参与分散初值的固定预算推断研究已由Windows端完成交付，Mac端正在独立接收和重建，其结果尚未计入本文。
\end{abstract}

\section{引言}
MCMC以相邻状态的递推依赖换取对复杂后验的可计算访问。多链并行同时运行多条轨迹；时间并行则尝试同时求解同一条轨迹中的多个位置。Newton类路径求解与增量Picard提供了两条具体路线\cite{zoltowski,grazzi}，但并行求值还会引入重复工作、导数近似和同步，其局部执行收益是否保留到后验推断，需要区别考察。

本文围绕两个问题展开：固定核参数、初值及实际随机输入时，时间执行能否更快完成同一递推；允许不同核采用各自配置后，所选后验函数的误差与工作流成本如何变化。第一类比较控制轨迹的统计信息，第二类同时受初始化、调参和混合影响。本文实现ParallelBayes，为这两类比较提供可复用目标接口、独立路径参考、实际输入与失败记录，并用指定CPU/CUDA条件下的实验解释成本差异。

模型访问与推断组件复用Stan、BridgeStan、BlackJAX和Pyro\cite{stan,bridgestan,blackjax,pyro}。compareMCMCs、PPL Bench与posteriordb已有跨引擎运行、基准或参考目标支持\cite{comparemcmcs,pplbench,posteriordb}；ParallelMCMC.jl和BayesForge分别覆盖时间并行MALA接口与R/JAX建模路线\cite{parallelmcmc,bayesforge}。本文增加的是同一实际输入下的执行比较和数值核验流程，以及这些流程揭示的成本与探索差异，不以统一R接口本身作为创新依据。研究限于固定维度连续参数、两类MH时间执行和成熟NUTS基线。

\section{方法与软件设计}
\subsection{目标与坐标}
设 $T$ 为相应自由坐标间的可微一一变换，原参数为 $\theta=T(q)$，计算使用无约束坐标 $q\in\R^d$，目标为
\begin{equation}
 \ell(q)=\log p(y,T(q))+\log|\det J_T(q)|.
\end{equation}
模型记录参数顺序、约束映射、完整数据、实现版本与指纹。两个提供方式可省略不同的参数无关常数，因此以 $\ell(q)-\ell(q_0)$、同坐标梯度及变换结果核对目标。正值测试例使用 $\theta=\exp(q)$ 和 lognormal 密度，其 $-\log\theta$ 项与 Jacobian 抵消。这一例同时用于检测遗漏 Jacobian 的实现错误。

R 是建模控制与分析入口。BridgeStan 在 CPU 上调用编译后的 C++ 密度和自动微分，Python 串行循环组织转移；原生JAX模型进入JIT和批处理；独立torch后端使用NumPy参考及显式CPU/CUDA执行，当前时间执行器仍含Python主机控制。Stan 模型指针不跨线程共享，Stan 内部线程关闭。此时高频调用边界的成本属于软件工作流，不能从跨后端差异直接推断并行算法的贡献。

\subsection{固定随机输入下的核}
MALA 的步长约定为
\begin{equation}
 q'=q+h\nabla\ell(q)+\sqrt{2h}\,z,\qquad z\sim N(0,I_d).
\end{equation}
接受对数比包含正反向提议密度：
\begin{equation}
 a(q,q')=\ell(q')-\ell(q)-\frac{\|q-q'-h\nabla\ell(q')\|^2-
 \|q'-q-h\nabla\ell(q)\|^2}{4h}.
\end{equation}
当 $\log u<a(q,q')$ 时接受，否则保留 $q$。随机游走 Metropolis（RWM）使用 $q'=q+s z$，接受对数比为 $\ell(q')-\ell(q)$。拒绝产生的自环计为一个转移。本文的 $h$ 不等于提议噪声标准差；这一约定在所有配对执行中固定。

随机输入由锁定 NumPy 版本下的 Philox 生成，采样与导数探测种子分开。比较固定的是噪声数组和对数均匀随机数组，而非跨软件的同名整数 seed。正式原始输出保存这些数组及其校验和。独立顺序参考 使用 NumPy 密度、解析梯度和显式循环，不调用待核验的JAX或torch转移函数。跨系统重建派生浮点数组不保证逐位一致；重复执行应传递已封存的实际数组，再分别核对文件与数组哈希。


\subsection{两类时间执行的共同数学对象}
普通MCMC逐步生成状态。时间执行器先猜测一个窗口内的路径，再修正相邻状态的不一致。固定初值和实际随机输入后，每一步都是确定映射，顺序路径满足
\begin{equation}\label{eq:recurrence}
q_t^\star=F_t(q_{t-1}^\star),\qquad t=1,\ldots,W.
\end{equation}
quasi-DEER用近似导数修正窗口；Online Picard用接受增量重建路径并提交连续一致的前缀。它们求解的是指定递推，核验比较的也必须是相同初值、核参数及随机数组。

\paragraph{quasi-DEER的窗口修正。}
给定第$k$轮路径，下一轮满足
\begin{equation}\label{eq:deer}
q_t^{(k+1)}=F_t(q_{t-1}^{(k)})+
B_t^{(k)}\{q_{t-1}^{(k+1)}-q_{t-1}^{(k)}\}.
\end{equation}
旧路径上的映射和矩阵可同时计算；随后把右侧整理为关于新前驱的仿射递推，用结合扫描求解。在精确算术、各次映射有定义、$B_t^{(k)}$有限且仿射递推精确求解时，第$k$轮至少恢复前$k$个状态，因而长度$W$的窗口至多需$W$轮。原因是固定初值使第一步正确；若前$k$步已经正确，下一轮保持该前缀，并使第$k+1$步的修正项为零。这是既有因果递推性质\cite{gonzalez,zoltowski}，不依赖$B$必须为真实Jacobian。它没有为浮点溢出、容差提前停止或一般后验误差提供保证。

\paragraph{硬前向与代理Jacobian。}
令$b=\ind\{\log u<a(q,q')\}$、$\operatorname{sg}$为停止梯度算子。本实现用
\begin{equation}
g=b+\sigma(a-\log u)-\operatorname{sg}\{\sigma(a-\log u)\}
\end{equation}
构造代理导数；前向仍返回硬接受/拒绝状态。torch代码另以停止梯度包裹硬输出，使前向避免软表达式的舍入抵消。这里得到的是代理Jacobian $J_{\rm proxy}$，不是硬MH映射的真实Jacobian。每链、每时间位置采用一个实际Rademacher向量$v_t$，在窗口迭代中复用，并设置
\begin{equation}
B_t^{(k)}=\operatorname{Diag}\!\left[
\operatorname{clip}\{v_t\odot(J_{\rm proxy,t}^{(k)}v_t),-1,1\}\right].
\end{equation}
截断作用于导数近似，不作用于状态。固定探针的复用不支持额外声称每轮自适应矩阵的条件无偏估计。

原论文伪代码先取$\log\alpha=\min(0,a)$，其平滑门控为$\sigma(\min(0,a)-\log u)$\cite{zoltowski}；本项目归档提交\texttt{5e5b637}的上游\texttt{samplers.py}与本实现使用未截断的$a$。两种硬接受判据等价，代理导数一般不同，故这里明确报告所测公式。本实现还采用非重叠窗口、重复窗口起点的初猜及硬残差停止，不使用上游的NaN归零或状态裁剪；性能比较针对该适配实现。

\paragraph{Online Picard的增量和确认前缀。}
已确认起点为$q_L$时，RWM的固定输入增量及候选路径为
\begin{align}
D_t^{(k)}&=s z_t\ind\!\left\{\log u_t<\ell(q_{t-1}^{(k)}+s z_t)-\ell(q_{t-1}^{(k)})\right\},\\
q_t^{(k+1)}&=q_L+\sum_{i=L+1}^{t}D_i^{(k)}.
\end{align}
在新路径的前驱上重算接受事件，只提交连续匹配的前缀。例如四个位置依次为“匹配、匹配、不匹配、匹配”，只能提交前两个。第四个位置的前驱尚未确认。由起点向后归纳，固定噪声下匹配的接受事件确定相同增量，因而确认前缀满足原递推\cite{grazzi}。torch批量执行对各链取最短确认长度共同推进，窗口尾部只处理实际存在的转移。浮点前缀和与顺序累加的次序不同，仍须分别检查路径差和接受事件。

\subsection{数值输出标准与失败处理}
quasi-DEER停止条件为硬递推残差
\begin{equation}
r=\max_{t,j}\frac{|q_{t,j}-F_t(q_{t-1})_j|}{\mathrm{atol}+\mathrm{rtol}|F_t(q_{t-1})_j|}\leq1.
\end{equation}
它控制局部一致性，而非长路径误差。独立NumPy参考另要求接受事件零失配，且每链无约束路径最大差不超过
$100[\mathrm{atol}+\mathrm{rtol}\max(1,\max|q|)]$，本文协议的两种容差均为$10^{-10}$。100倍系数是指定输出标准，不是误差传播界。全路径尺度会放宽小尺度坐标的阈值；后续逐坐标和函数差只能作为另列的描述，不能追溯改变原合格判据。

迭代耗尽、非有限值或独立审计失配的输出保留原记录，不转换为普通后验样本。当前MH实现把非有限提议密度统一视为失败；合法的支持集外提议密度$-\infty$尚未一般地区分，因此有界支持目标的适用范围受限。NUTS的发散与返回有限数组分别记录。显式顺序回退复用原数组重算整个轨迹并计入失败费用，本文实验不启用回退隐藏求解失败。

\subsection{R用户如何运行和扩展}
安装版示例以二维Poisson回归为例，$y_i\sim\operatorname{Poisson}(\exp(X_i\beta))$、$\beta_j\sim N(0,4)$。外部Python模型提供框架密度、独立NumPy密度/解析梯度和恒等参数变换；R整批调用，再转换为\texttt{posterior}对象。以下为仓库中实际示例的调用顺序，环境变量在启动R前指定，输出使用不存在的新目录。
\begingroup\small
\begin{verbatim}
# Once: create the shared data and actual random arrays
python examples/installed_custom_target.py prepare \
  --output inputs
# Set R_LIBS_USER and RETICULATE_PYTHON before starting R
Rscript --vanilla examples/installed-custom-target.R \
  torch inputs output cpu
\end{verbatim}
\endgroup
R脚本核心调用如下；\texttt{example\_dir}定位随包交付的示例文件，\texttt{inputs/output}为上述目录。
\begingroup\small
\begin{verbatim}

  "installed_custom_target", path = example_dir, convert = TRUE)

  if (!identical(w$status, "completed")) next

\subsection{函数误差、参考和诊断}
对预先规定的函数$f$，记录四链平均估计$\widehat\mu_{a,f}^{(r)}(N)$，逐函数误差为
\begin{equation}\label{eq:error}
\widehat E_{a,f}(N)=\frac{1}{R}\sum_{r=1}^R
\frac{(\widehat\mu_{a,f}^{(r)}(N)-\mu_f^\star)^2}{s_f^2}.
\end{equation}
有解析期望时这是重复MSE的估计；有限MCMC参考下只能称参考平方差。历史分析还报告函数间最大值，紧凑研究以逐函数结果为主。所有实际函数定义列于表\ref{tab:functions}；标准化已包含在部分函数本身，其余函数没有转成相同实际意义的相对误差。当前误差计算的额外$s_f=1$。历史阈值$\epsilon=0.1$即平方误差$\epsilon^2=0.01$，对应函数单位中的RMSE 0.1；它是比较标尺，不是每种应用都充分的精度要求。误差估计的重复不确定性和参考MCSE均另列，不与$\epsilon$混用。

历史Mac采用24重复、4000次逐点bootstrap；原Windows每格只有4份输入，其bootstrap区间只作探索性描述，正文直接展示配对点。紧凑研究主任务按完整四链重复整体重采样，采用9999次逐点BCa、至少20份共同可用重复；退化区间保留未定。缓存每格仅4份输入，不计算BCa。失败率使用全部计划重复，误差/费用的成功条件统计明确标注；它们不等于包含失败损失的无条件风险。

\subsection{调参、预算与三种成本边界}
历史零初值和固定MH步长定义的是指定工作流。新紧凑研究沿用独立开发试验选定的仿射坐标和步长：每目标/核六个候选，每候选两份四链输入，按两次都合格后的平均ESJD/d选择。216次计划开发运行中212次完成、4次失败；该规则优化移动距离，不证明ESS或函数误差最优。正式MH初值在采样坐标中取$N(0,4I)$，M1首坐标分置两侧；窗口32，quasi-DEER每窗口最多2048轮，Picard最多$N+512$轮。CPU Pyro NUTS使用四进程，每链预热1024步、目标接受率0.8、最大树深8；MH舍弃512步。开发调参费用单列，不能隐记为零或假定每次拟合重新支付。

紧凑研究固定两档保留预算1024/4096及24重复。该设计因用户硬件与空间条件在旧大网格启动后修订，保留旧证据并用新身份和输入，不能称完全事前预注册。Windows端已完成计算、分析和上传，交付提交为94bebec。Mac端已核对冻结源码并完成有限技术组件的独立重建，全部正式原件正在分块接收；正式研究的误差、费用和失败结论将依据完整重建纳入正文。两个已测预算点不用于插值精确达标时间。

计时分别回答三个问题：缓存执行衡量准备后的内核；普通批量工作流包含进程启动、输入/目标、适应或丢弃、采样、变换、输出和R诊断；研究审计另含独立顺序参考与完整证据检查。CUDA边界显式同步，后两种口径为嵌套边界，不相加。历史Mac的普通内存口径只是从已有计时扣除审计的记账估计；后继进程测量才是直接观测。两者仍不含最外层R前端、环境安装和全局归档传输；R完整调用须另批测量，不能回填历史主任务。误差与时间使用同一组函数可用重复，缺少完整计时的任务不能通过删行产生曲线。

\section{实验结果}
\subsection{路径一致性与统计校准是不同检查}
Mac的1920项和Windows首轮的512项均通过各自规定的数值输出检查，独立参考的接受事件零失配；最大路径差分别为$2.36\times10^{-8}$和$5.212\times10^{-10}$。两者容差尺度与实现不同，不能用这两个最大值作算法精度排名。跨系统诊断重建还发现小数读取与中位数末位变化影响秩诊断；改用实际二进制输入后，剩余差异定位于折叠分量，未改变相关任务诊断不良的判断。详细定位及失败记录进入补充材料。

SBC采用$\theta\sim N(0,1)$、$y_j\mid\theta\sim N(\theta,1)$，$j=1,\ldots,8$，解析后验为$N(\sum_jy_j/9,1/9)$。在同一批64数据集上，解析90\%区间覆盖54例；MALA及其时间执行也覆盖54例，但与解析区间有4例覆盖分歧。RWM及NUTS覆盖53例。总体比例接近不能说明逐数据集区间相同，五种工作流也不能算五份独立校准证据。端点、后验矩和数据依赖对数似然秩另列；测试量的选择决定SBC能发现哪些问题\cite{modrak}。

\subsection{为什么较快的执行未必提供更有用的样本}
CUDA的A1/RWM、512步配置中，Picard缓存执行约快4.09倍，但提议全部被拒绝，链停在初值，执行器每轮可确认整个窗口。自环降低了路径求解难度，同时使后验探索失效。这一反例解释了确认前缀与统计效率的区别，不能只按每次确认转移的成本推荐执行器。

窗口扩大还会增加重复工作。Mac机制实验中，G1四链Picard将窗口16增至64，每轮确认数的组中位数仍约5.57，而前向映射次数由5.50升至20.88次/输出转移，缓存速度比从0.402降至0.170。G2单链quasi-DEER的平均窗口轮数由11升至22.25，速度比从0.051降至0.027。拒绝自环均计入分母，JVP另计。

Windows机制协议也包含G2 RWM步长对照、窗口4/16及链数分配。quasi-DEER每输出转移需7.75--22.5次前向映射及3.875--11.25次JVP；Picard需2--7.59375次前向映射。部分零接受配置一次确认整个窗口。等512总输出的另八个对照中，16条短顺序链比单条较长Picard链快4.43--6.92倍，但轨迹长度和初始化不同，不能据此比较共同精度。各模型只有两份机制输入，操作探针还会扰动执行；现有结果支持额外工作与减速相容，尚不能唯一分离JVP、扫描和主机控制的因果贡献。

\subsection{固定预算误差与探索诊断}
历史Mac较长预算2048步时，MALA的两个执行器均在两个目标上取得最大函数误差区间低于0.01；RWM亦为两个，NUTS为五个。同核配对误差在原表显示精度下相同，正文合并解释，执行费用分别报告。L1/L2使用有限参考，L2的全函数判定仍未定；完整数值、区间和全部目标在补充材料保留。

NUTS的2358次发散和6861次积分上限命中均来自中心化漏斗H1；双峰M1没有发散，但两个预算的最大参数$\hat R$约1.73，函数误差仍高。Windows首轮则有480/512次拟合至少一个有限$\hat R>1.01$，108次含常量变量或函数。数值核验成功、有限函数误差较小与整体探索充分并不等价。已交付的紧凑研究使用独立调参和更长预算；完整原始结果的Mac重建尚未结束，本稿目前不报告其结果。

\subsection{水井案例的推断任务}
W1使用posteriordb的3020个观测，模型为
$\Pr(y_i=1)=\sigma(\alpha+\beta d_i/100)$，保留原模型对$\alpha,\beta$的平坦先验。问题是距离与换井概率的关系，以及0米、100米处预测概率的估计成本。两个不同距离处均出现异结局观测，足以证明该二维后验可正规化（补充材料附录）。Stan、NumPy、torch密度及导数和Windows的CPU/CUDA/R数组路径已有核验；正式误差—成本结果随紧凑研究接收。稀有符号事件和非认证求积误差仍分别呈现。该案例已参与开发，不能称未见模型族测试。

\section{讨论与结论}
现有证据表明，时间并行能否降低成本取决于批处理节省的时间能否抵消重复映射、代理导数、扫描与同步。Mac负结果和Windows Picard的局部执行收益都可由同一问题理解：并行宽度增加了可同时计算的位置，却不保证增加有用的路径推进。全拒绝例进一步说明，容易求解的轨迹可能没有推断价值。

这些结果不构成CPU不适合时间并行的普遍判断。Picard原文在Apple M3上对由时滞微分方程定义的昂贵黑箱似然报告约2.52倍墙钟收益\cite{grazzi}，成本结构不同于本文多数廉价目标。本文适配的窗口与停止规则也不同；精确恢复的因果性质不能消除浮点容差、初值和后验混合的影响。

本版软件使研究者能够定义目标、共享实际随机输入、检查指定执行器并保留失败，但尚非任意Stan模型的时间并行入口。Pyro NUTS是研究CLI，最外层R完整费用仍待有限测量。比较也没有覆盖MEADS、LAPS等全部现代多链策略\cite{meads,laps,fsm}。现阶段最适合的用途是核验与比较已明确实现的目标和执行方式。

最终推断结论须依据紧凑研究的逐函数误差、诊断、失败与同一集合上的成本形成。预算不足时报告不足，而不按是否出现正加速决定追加配置。当前贡献是可重复使用的研究实现、配对执行证据及其机制解释；新算法、通用自动选择和普遍推断加速不在已完成贡献中。
