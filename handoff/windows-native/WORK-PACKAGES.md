# Windows原生执行登记模板

基线：cpu-review-v1；用户于2026-10-04恢复Windows阶段。台式机首次运行时在开发分支新建`execution/windows-native/WORK-PACKAGES.md`，按实际结果更新，不能把此模板的命令当作已执行证据。

| 阶段 | 初始状态 | 验收产物与进入下一阶段的条件 |
|---|---|---|
| S 技能 | 待迁移/核验 | 按SKILLS-SETUP.md安装30个私下转交技能，核对插件，保存skills-status.json；区分复制、发现、运行通过与平台限制 |
| W0 环境 | 待Windows实测 | nvidia-smi、系统/驱动/Python/torch/架构清单，float64/grad/JVP/vmap实测，完整依赖锁；失败停止GPU相关工作 |
| W1 模型与顺序核 | 待开发 | PyTorch CPU＋CUDA目标与独立NumPy密度/梯度/Jacobian核对；实际随机数组；RWM/MALA硬接受规则及失败输出 |
| W2 两个执行器 | 待开发 | PyTorch quasi-DEER MALA、Online Picard RWM；scan次序、末窗口、拒绝自环、容差、接受分支、停止/回退与错误注入通过 |
| W3 接口和统计 | 待开发 | 原生Windows R端到端、posterior顺序；解析矩与小型SBC并配解析对照；定义并验证外部NUTS基线或明确缺失 |
| W4 小型探测 | 未冻结 | 同Windows、同PyTorch、同核的CPU/GPU/执行器对照；同步计时、GPU驻留、额外工作、显存及失败；不追求正加速 |
| W5 新正式协议 | 待W4证据 | 在观察正式结果前冻结windows-native-v1；源提交/依赖/设备/数据/实际随机数组/坐标/精度/预算/误差/失败规则；不得复用旧CPU协议名称 |
| W6 正式实验 | 未开始 | 所有预定任务终结/失败记录完整，检查点可恢复；研究审计和正常工作流分开；参考不确定性保留 |
| W7 回传 | 未开始 | Windows开发分支＋提交；可核对任务状态/原始数组/协议/锁/日志/校验和及结果包；修订论文仅写实际证据 |

每阶段记录开始/结束、实际命令、源码提交、关键文件哈希、测试数量及失败/跳过数量。不设人为总时长上限，保留内存门槛、迭代上限和失败停止；系统休眠或中断后核对哈希再恢复。

依赖开发的命令目前不存在，必须由Windows Codex实现并记录。禁止编造`--backend torch`、GPU NUTS或一键采样命令并写“已通过”。升级科学实现、精度、函数或停止规则需新协议身份；纯兼容修复保存补丁并复核相关路径，不覆盖历史已完成结果。
