# 缓存伴随分析：按原输入配对的成本统计

2026-10-06；源码`5ccc0d6`。本轮完成`cache_probe_analysis.py`及独立重建入口。它接在[事前测量设计](FORMAL-MEASUREMENT-DESIGN.md)之后，尚未接入正式原生Windows worker；没有新增MCMC、设备计时或正式研究结果。使用tdd检查已约定的统计接口，并用nature-statistics核对重复单位、缺测和声明范围。

## 输入到统计结果

`create_cache_plan(allocation, primary_tasks, model)`重建事前选择表，在该目标所选原输入上创建独立缓存伴随重采样计划。正式草案为128输入中每批32预选8个，共32个。命名空间绑定完整分配哈希；主推断的128行索引或其他分配表的索引不可混用。所有缓存预算与方法共享同一实际索引数组，9,999次；用既有`save_plan`/`load_plan`保存和核对。

`analyze_cache_probes(allocation, primary_tasks, plan, bindings, observations)`要求该目标全部计划探测，包括未开始和失败者。每个探测都提供事先核对的实际输入文件SHA256、所用前缀tape SHA256、目标ID、完整配置，以及初次执行和三次重放的有序记录/明确状态。缺计时记录用`None`，不删槽位。输入、目标、初值和同核配置的配对错误被拒绝；同核比较只允许执行器与数值迭代上限字段不同。实际源文件、数组和独立数值审计仍须由调用端验证，统计接口本身不提供新的轨迹证明。

接口不接收“原主任务是否成功”作为筛选条件。主任务失败也保留事前入选探测；探测输出不挽救失败主任务。单探测只有初次与全部重放均满足输出标准且记录完整才生成缓存点，点值是三次准备后执行的中位数。每个原输入只贡献一个点，三次重放不是三个独立重复，也没有新增后验样本。

| 输出 | 解释 |
|---|---|
| 每方法均值与逐项区间 | 条件于该方法缓存点可用的输入，不是普通推断耗时 |
| 配对费用比 | 共同可用输入上的`exp(mean(log(T顺序)-log(T时间)))`；大于1表示较低缓存执行成本 |
| 四格表 | 两方法均可用、仅顺序、仅时间、均不可用；覆盖全部32计划输入 |
| 可用性分类 | available、failed、interrupted、not_run、incomplete_record；不等于算法收敛分类 |
| 执行状态 | 另保留每次调用的valid、数值/资源/未分类失败、基础设施中断、未运行六类；不把它们当独立n |
| 实际消耗 | 全部已记录初次/重放执行时间之和，包括失败；任一时间未知则完整总量为null，已知部分仍保留 |

可用性分类先保留任何明确失败，再列基础设施中断；全部未运行者单列，其余不完整记录单列。逐次状态完整保存，故混合失败与中断不会被总体分类掩盖。数值输出有效但计时回执丢失，归为`incomplete_record`，不伪造时间或改称数值失败。失败准备或归档等外层费用不在执行器时间里，仍由各自账本记录。

至少20个共同可用输入且BCa非退化才形成费用比区间。点值可以在更少输入时显示，但同时给出不足原因、有效数和不可用区间。日志尺度区间另指数变换到费用比尺度；不取最快重放、不以出现正加速为验收。常量比例不产生零宽区间。

## 复现

从相容源码和既有NumPy/SciPy环境，在项目根目录运行；输出目录必须不存在：

```text
python scripts/completion/validate_cache_analysis.py --output NEW_DIRECTORY
python scripts/completion/validate_cache_analysis.py --audit NEW_DIRECTORY
```

第二条只读并从保存的计划、输入声明、逐次记录及索引重建标量和bootstrap数组，不调用采样器或计时内核。输入文件SHA256在这个人工夹具中是声明性假值，仅用于配对检查；正式运行的适配器必须从实际封存资产产生。

## 仍需关闭的边界

当前实现为草案中的整体输入重采样，未改为按机器负载/批次的分层或时间序列模型。32个输入和9,999次重采样不保证区间覆盖率；跨批负载漂移或相邻计时相关不能由此消除，实际运行仍需保存顺序、负载和批次信息并在解释中呈现。该伴随框架与主推断框架共享原输入，不能当作独立证据。

正式缓存worker、实际审计回执适配、批次费用衔接、Windows进程/资源验收与F2回传尚未完成；正式协议未冻结。没有把缓存时间替代普通推断的误差—成本横轴，也没有据此生成新的科学结论。
