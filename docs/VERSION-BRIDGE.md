# 0.1.0至0.1.1的证据衔接

CPU主实验属于0.1.0／protocol-v1；0.1.1是独立发布候选，正式SBC属于0.1.1／statistical-v4。旧性能结果不能自动代表新版本的性能。

| 修订 | 数值／行为影响 | 计时影响 |
|---|---|---|
| 约束输出有限性、正值下溢及Stan往返检查 | 原来可能返回的不可表示输出改为失败；一般有效输出仍须对照 | 新增变换检查，Stan有逐行往返；性能不等同 |
| quasi-DEER末窗口的真实步掩码与终点 | 非整窗口配置可能改变停止和输出；整窗口也可能改变编译程序 | 掩码操作可能改变编译/执行耗时 |
| 失败路径、部分链与oracle异常保存 | 失败行为和诊断改变；正常目标的转移公式未改 | 异常分支及记录开销可能不同 |
| 恢复环境、传递依赖锁与session记录 | 拒绝不同环境的续跑，不改变既有轨迹 | 实验驱动及写盘记录有额外开销 |
| Stan audit请求明确拒绝 | 旧版本未兑现独立核验的请求被拒绝 | 不能把旧请求与新成功运行视为同条件 |
| R单元素数组往返和Python版本检查 | 修复单参数／单元素输入语义 | 不据此宣称R性能相同 |

修订后冻结一个有界对照：主协议8目标×5工作流，取原replicate=0、较短预算；MH复用原始保存的实际随机数组，NUTS复用锁定实现的原seed。旧源码从存档解压，并以明确PYTHONPATH在独立进程调用；当前源码另行调用。保留每个来源模块、原始数组校验和、结果与路径差。

运行入口：`scripts/revision/version-replay.py`；输出：`execution/cpu-revision-v1/version-replay/summary.json`。这些对照用于数值衔接，不是受控计时实验；不据路径相等宣称性能相等。边界行为的区别另由已有安全测试覆盖，不能用正常目标零差替代边界核验。

完整历史补丁与两版本源码随独立复现包交付。未默认重跑1920项主实验，也未将其重命名为0.1.1结果。

实际完成：40/40组返回有效输出，最大路径差1.9895196601282805e-13，接受事件失配0。原始新旧输出与日志均保存，未重测或升级旧版性能结论。
