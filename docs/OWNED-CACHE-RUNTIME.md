# 缓存测量的原生进程管理与产物隔离

2026-10-06。后继于 CACHE-PROBE-EXECUTION 的数值/文件接口；在独立
`codex/measurement-runtime` 分支开发，不覆盖原审查工作树与安装候选。
这是正式测量所需的运行器衔接，仍不是正式推断研究或 Windows 验收。

后继 [失败保留接收](OWNED-CACHE-FAILURE-EVIDENCE.md)已补齐有限 Mac 失败/中断/未启动布局及统计衔接，原成功运行记录不变。

## 解决的问题

原 runtime-v1 把 `status=completed` 固定解释成 `samples_eligible=true`。
缓存探测即使四次执行全部通过独立审计，也只产生测量资料，因此无法诚实地接入
该接口。本版任务在启动前声明 `artifact_kind`：默认 `posterior` 保持原采样语义；
`cache_measurement` 的完成状态对应 `measurement_available=true`，
而 `samples_eligible` 始终为 false。

工作程序不能切换任务类型，失败与基础设施中断均不产生合格样本或测量点。
缓存的成功历史使用独立的 `measurement_available` 结果类别，后验费用分析拒绝
此类历史，不能把缓存重放当成新的推断重复。未知类型在任务登记前拒绝，
避免形成缺少进程回执的虚假运行项。

复用同一共享登记、操作系统锁、Mac fresh process group、采样 RSS 观察、
磁盘预检和逐调用成本账本。成功/失败终态可显式零重算核验；缓存中断不得重试
以凑齐三次成功重放。原后验任务仍保留原来至多一次显式基础设施恢复政策。
没有设置总运行时间截止。

## 检查覆盖

9项新增行为检查通过，另有17项受影响运行器、协调、恢复及费用检查通过。
新增检查覆盖：完成的测量不成为后验样本；终态零重算；后验费用分析拒收；
三种产物/资格矛盾；未知类型拒绝发生于登记前；中断测量不重试；
人工128MiB分配触发64MiB采样RSS保护；管理者中断后存活测量进程阻止后验任务。
实际进程观察与自建进程清理都有执行；不是仅检查返回码或过期PID文件。

进程组约束要求工作程序及后代不逃离该组；RSS是间隔观察，可重复计入共享页，
不能宣称无遗漏的硬内存上限。Windows Job Objects、CUDA资源及其恢复语义仍须
原生验证，Mac结果不替代它们。

## 实际运行与重建入口

短协议复用原 cache-probe-capsule-mac-v2 的四份输入，G1/L1、每模型两份输入，
四种CPU MH组合、每链16转移（其中8步为原丢弃段配置），共16个探测/64次执行。
最大形状协议复用原 batch-schema-maximum-mac-v1 的G2输入，64维、4链、
512步丢弃段加16,384步保留段，四种MH组合各一次初始加三次准备后执行。
两份协议独立封存，不合并重复数，不重新生成随机数组，不再执行原中断最大NUTS。

实际进程测量、全部核验和费用计入新技术身份；这些输入都曾用于技术开发，
不是独立正式研究或模型留出集。内核、工作程序及整个协调调用是嵌套计时，不能相加。
该短/最大形状验收不估计一般速度提升或缓存稳态；最大维度也不等于所有目标的
计算最坏情况。
