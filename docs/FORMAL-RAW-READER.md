## 已接通的科学读取

`formal_science.ScientificReader` 在初始化时核对归档源码及当前科学读取依赖，以独立 NumPy 目标重建固定仿射坐标。W1 使用显式归档的八文件来源和已有可积性检查。每次 `read` 接收冻结任务 capsule、任务历史导出、结果位置、外层调用账本与**单任务**文件清单；不访问原 Windows 的活动登记，也不调用 Windows API、torch/JAX 采样器或重建随机流。

逐任务核对后返回：

- 原始任务状态、全部尝试及成本口径。失败、中断、未运行和费用未知保持区别；读取错误另存 `READER-FAILURE.json`，不改写采样器的原始结果。
- 实际五类输入的文件、数组、形状、精度及地址；只缓存一份输入和一个目标，逐拟合处理原始数组。
- MH 保存设置、设备、精度、输入前缀和审计记录；再用独立 NumPy 对四链全路径与接受事件重放。阈值仍是原来的 `100*(atol+rtol*max(1,maxabs(saved_chain)))`，不删除拒绝自环。
- NUTS 独立的初值、种子、初末 RNG 状态、预热形状、四条子链、保存的 Job 成员观察、适应步长及配置。保留各子链发散和未知树深度命中数，不套用 MH 路径等价保证。
- 原坐标函数、均值及现代 R 诊断；先核对有界二进制传输身份和长度，再执行 R 二进制往返。常量函数等 `null` 不变成理想诊断值。
- 缓存四次调用的完整/部分证据。完整缓存时间必须四次都有效；中断后已测费用仍计入记录，缺失时间不填零。缓存始终没有后验样本资格，也不增加独立重复。

普通工作流、含审计研究执行、额外核验和全部调用继续使用原成本政策，不累加嵌套时间。逐链 NumPy 重放是接收端验证成本，不混入原 Windows 运行时间。

## 跨平台重建口径

默认要求函数和诊断精确重建。显式启用 `cross_platform=True` 时，接收端比较使用冻结的输出 `atol/rtol`，原 MH 路径/接受条件不变。

汇总数据保留**原 Windows 均值和诊断**。Mac 重建均值另存；接收端函数二进制为 `functions.receiver.bin`，R 的输入是原 Windows 二进制的副本，分别记录哈希。这样即使接收端存在符合既定比较条件的末位差，也不会悄悄更换论文的统计输入。原运行的函数失败在接收端成功时仍保留失败资格。
