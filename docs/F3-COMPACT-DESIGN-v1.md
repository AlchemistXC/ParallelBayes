# F3 紧凑实验设计 v1：启动后的资源修订

2026-10-08。用户确认旧正式网格已开始采样，并要求按现有硬件重新设计，新增磁盘预算约50–80 GiB。本文件替代旧完整网格的后续执行安排；旧冻结协议、源码、已完成/失败/中断数据全部保留。当前已完成的是设计和容量计算，**新版冻结/执行/接收适配尚未实现或原生验收**。

## 1. 研究问题与修订边界

保留两个问题：同核、相同实际随机输入下，顺序与时间执行在同机CPU/CUDA上的费用有何不同；在两个固定预算下，九种完整工作流的函数误差、诊断与失败如何。CPU NUTS仍为跨核基线，不能把与CUDA MH的差异归因于单一执行技术。继续使用原生Windows 11、AMD CPU和RTX 5080，无需新增平台、语言、GPU NUTS或选择器。

这是**采样启动后的资源驱动修订**。作者已接触开发、机制和有限验收结果；旧正式结果的实际可见范围由Windows补录。新身份和新随机数组减少复用问题，但不使修订变成完全事前预注册。不能用旧成功/较快的任务补足新重复数，也不按旧正式结果选择保留模型。

## 2. 固定的新规模

新身份：`windows-compact-inference-v1`。机器可读设计与账本见 [design.json](../benchmark/designs/windows-compact-inference-v1/design.json) 和 [storage.json](../benchmark/designs/windows-compact-inference-v1/storage.json)。它们是设计材料，不能送入旧版prepare或formal_batch。

| 维度 | 旧完整方案 | 新方案 |
|---|---:|---:|
| 目标 | G1/G2/A1/L1/L2/H1/H2/M1/W1 | 全部保留 |
| 工作流 | 9 | 全部保留 |
| 每目标独立四链重复 | 128 | 24 |
| 每链保留步数 | 256/1024/4096/16384 | 1024/4096 |
| 主任务 | 41,472 | **3,888**（3,456 MH，432 NUTS） |
| 正式实际输入文件 | 1,152，最大16,896步 | **216，最大4,608步** |
| 缓存探测 | 9,216 | **256** |
| 缓存数值调用 | 36,864 | **1,024**；均不计新增样本 |
| 预定批次 | 4×32重复 | **3×8重复** |

九工作流为CPU和CUDA各自的顺序RWM、Online Picard RWM、顺序MALA、quasi-DEER MALA，以及CPU四进程NUTS。主任务减少90.625%，缓存探测减少97.222%。任务数量不是耗时预测；NUTS预热、启动、求解轮数与独立审计仍有成本。

每批1,296主任务。缓存选择G1（便宜低维）、G2（高维稠密求值）、L2（较大logistic似然与未定事件压力目标；采样采用既定仿射坐标）、W1（实际数据外部目标）；以计算结构覆盖为理由，不宣称覆盖所有模型的缓存表现。固定使用重复编号0、8、16、23，在两个预算、两个设备和四种MH工作流上配对；三批分别64、64、128探测。失败不替换，未完成不按成功补齐。

保留旧目录中的模型、数据、仿射坐标、步长、函数及尺度。四链、MH舍弃512步、NUTS预热1024步/树深8/目标接受率0.8/对角质量矩阵、四worker各一线程、torch四线程、窗口32、quasi-DEER每窗口最多2048轮、Picard最多保留预算+512轮、atol/rtol均1e-10全部不变。初值仍为仿射坐标N(0,4I)，M1首坐标分置两侧。减小预算不等于放宽轨迹核验。

## 3. 分析与可支持的结论

独立单位是一次原始四链重复。设备、工作流、两个预算共享同一次原始输入块；缓存初次及三次prepared调用都是技术重放。新身份应独立派生随机输入和任务顺序，封存真实数组；文件名相同不代表允许与旧目录共用文件。

- 保留全部36个原输出函数、rank-normalized/folded Rhat、bulk/tail ESS及NUTS诊断。L2未定符号事件与W1非认证数值积分参考保持局限，不填真值。
- 保留原逐格点态双侧95% BCa、9,999次重采样和至少20个可用独立重复的规则。共同配对整组重采样；失败使配对可用数不足20时，区间为未定，不补样本或换区间凑完整。成功样本的误差/费用统计是条件性描述，旁列全部24次的资格、失败与未知费用，不能从分母删除失败。
- 不作“所有模型总体优胜”的显著性检验；点态区间不是多重比较同时置信带。24重复不是经功效计算证明充分。某格24次均未失败时，二侧95%精确二项区间失败率上界仍约14.25%，不认证稀有失败。
- 缓存每格仅4份原输入：展示各输入三次prepared计时的中位数、配对速度比、范围、成功/失败/缺失次数，不出BCa区间，不把12次重放当n=12。普通主任务费用可按24份配对分析，不能替代缓存n。
- 只回答1024/4096固定预算比较，不估计精确达到指定精度的时间；缩短链长可能增加诊断不足，H1/H2/M1不得因此剔除。数值接近的路径不自动成为严格相同轨迹或收敛证明。
- 三批均预定完成；批间仅检查资源、完整性、数值资格和进程状态，不按速度/MSE好坏停止或追加。真实资源不足可暂停并保留未运行状态，不当作数值失败。

## 4. 空间安排

以下由现有保存格式逐数组计算，假设每任务一次成功、不重试、保留当前1MiB/任务故障记录预留；不依赖压缩率。它既不是实际最低占用，也不是容量上界。

| 条件账本 | GiB |
|---|---:|
| 主结果、216输入、缓存和原诊断命名数组 | 19.90 |
| 4,144成功尝试的现有预留 | 4.05 |
| Windows一份原件合计 | **23.95** |
| Mac原件加接收函数文件 | **27.51** |
| 双机各一份，合计 | **51.46** |
| 额外保留第三份全量包的三副本情景 | 75.41（尚无日志等） |

建议双机新增空间合计按**60–75 GiB预留、80 GiB作规划上限**；例如Windows约30–35 GiB、Mac约30–40 GiB，由实际卷余量决定。此分配仅是规划，不能替代运行前逐卷检查。若50 GiB是两机合计，低于上述不依赖压缩的账本，不能据此直接放行；使用已授权上限范围安排可用空间，不自动买设备、删旧证据或改变科学网格。

不在任一机器同时保留完整原件、完整tar和完整解压树。交付采用逐文件/有界分块校验，缓冲建议≤1 GiB，接收完成块后验证再继续。**当前归档工具尚须核验是否真正有界；若先生成全量tar，就不符合本方案。** 不通过删除原始结果、故障预留或诊断来实现账本。额外缓存副本仅在其完整性与可恢复性已验证后按约定清理，原证据保留。

以上不含旧已启动研究、日志、失败重试、JSON/SQLite、文件头/分配、环境和历史。旧研究占用与已付计算时间单独登记，计入实际卷余量；不能凭“新增80 GiB”忽略它。每批后更新实际增长并重算剩余容量；超过规划范围则资源等待，不静默删模型。仍无总实验时间截止，保留数值、内存、磁盘和进程保护。

## 5. 从已启动旧研究迁移

先执行[暂停与保全提示词](../handoff/windows-completion/CODEX-PROMPT-HOLD-FORMAL.md)，取得停止新派发、登记和原生Job无活动进程的回执。Mac没有Windows实时句柄，当前不能声称已经停机。

旧formal_batch没有pause参数；Coordinator的异常处理可能吞掉Ctrl+C后继续下一任务。Windows必须通过当前真实PID/创建时间/命令行及受管理父Job准确终止本研究driver，不能批量结束Python。终止后只做登记对账/快照，**不能运行旧formal_batch --resume来“检查”**，因为它会继续采样。既有错误原分类和未封口文件保留，停止意图另记，不覆盖为成功。

旧协议封存为资源原因中止的研究，记录修订前可见结果、已完成/失败/中断/未运行任务、数组与哈希、未知/已知费用。旧结果可独立披露，不能合并进新24重复或抹掉。新环境可以保持旧已验证版本，但新源绑定、协议、输入地址和输出根必须独立。

## 6. 开发、验收与结束条件

新版提示词见[紧凑实验接力](../handoff/windows-completion/CODEX-PROMPT-COMPACT-STUDY.md)。先适配新schema、216输入、3批、64/64/128缓存及n4分析，再对变更作有限原生验收；不得修改旧函数常量冒充原验收继续有效。原有限16用例/27主任务证据可以作为未变数值内核的基础，不能替代新的封存、调度、恢复与接收测试。

| 有限差异验收 | 独立技术身份；G2/4096和W1/1024各9工作流=18主任务，MH各8探测=16缓存；两次恢复新增执行0，原件不变；不计正式n |

本版不更改现有论文实验结果，也不宣称研究完成。若资源依然不足，应新建有理由的后续修订；不能临场选择顺利完成的子集。

缓存资格补充：每份输入的初次调用和全部三次prepared回放均通过完整路径/接受事件核验且计时齐全，才计算三次prepared计时的中位数；任一失败、缺失或不合格时，该输入中位数及对应配对速度比为未定。全部逐调用计时与失败仍展示，不用成功子调用的中位数替代。

主任务失败不取消已预定缓存探测；缓存成功不回填主任务为成功。有限验收前提交干净候选源并绑定完整清单；正式冻结使用同一清单，变更则按影响重验。技术包先在Windows独立目录模拟接收，不能称Mac独立接收。
