## 一、问题和本轮不再扩大的范围

回答两个问题：同一目标、核参数、初值和实际随机输入下，指定时间执行器付出多少额外工作、带来多少执行成本变化；在固定预算的四链推断任务中，这种变化是否仍伴随有用的函数估计、现代诊断和可接受的失败率。跨设备和不同核只解释为完整工作流比较。

主研究在同一台原生 Windows 11／AMD CPU／RTX 5080 机器完成。Mac 负责开发、独立参考和重建，不再复制整个正式网格，也不将旧 Mac JAX 数据与新 torch 数据合为同后端硬件排名。GPU NUTS、Windows Stan 编译、融合 GPU 控制、新语言和自动选择器均不作为本篇完成条件。

允许正式结果全部减速、压力目标预算内不达标或部分参考未定；这些不自动要求增加模型、改变核或继续运行到得到有利结果。

## 二、有限网格

| 维度 | 草案决定与理由 |
|---|---|
| 目标 | G1、G2、A1、L1、L2、H1、H2、M1、W1，共九个；保留困难目标及真实水井案例 |
| 目标身份和坐标 | 复用独立调参所锁定的目标 ID、仿射中心与因子、核参数；正式数据不参与修改 |
| 预算 | 每链保留 256、1024、4096、16384 步；前三个衔接预算预实验，最后一个为事先决定的四倍延伸，不承诺覆盖收敛区间 |
| 链与重复 | 每次完整拟合四链；每目标 128 次独立重复，重复是四链整体，不是单链或单个样本 |
| MH 初始阶段 | 固定核先执行并丢弃 512 步，计入成本；不声称已经达到平稳 |
| MH 初始化 | 固定坐标中独立 N(0,4I)；M1 首坐标交替 −5、+5、−5、+5；其余分量按相同规则。均衡初值不证明跨模式移动 |
| NUTS | CPU Pyro，四个 spawn worker，各一条链；每链 1024 步适应、目标接受率 0.8、对角质量、最大树深 8；保留发散，无法获得的诊断标为未提供 |
| CPU MH 资源 | 单进程、四个 torch intraop 线程；记录 interop、BLAS/OpenMP 设置和实际 CPU 时间，不称独占四物理核 |
| 时间执行窗口 | Picard 与 quasi-DEER 固定 32；窗口 8/32 的就绪核验及 F2 机制扫描另行呈现，不用正式误差选择窗口 |
| 浮点与输出 | float64；冻结既有完整路径状态容差和接受事件零失配要求；禁止因长路径失败而放宽 |

每目标／预算／重复有九个工作流：CPU 顺序 RWM、CPU 顺序 MALA、CPU Picard RWM、CPU quasi-DEER MALA；CUDA 上对应四项；CPU 四进程 NUTS 一项。同设备执行比较须同核同输入。CPU NUTS 与 CUDA MH 的差异包括软件和设备成本，不能仅归因于时间并行。

共 **41,472 次四链拟合**，其中 MH 36,864、NUTS 4,608。拆为四批，每批 32 次重复、10,368 个拟合，四批均为预定任务；不得因效果好坏提前停止或追加。分批只用于恢复、存储和执行管理，不开展效果驱动的中期决策。数值失败按预定规则终结，不能自动重抽输入。每个预算是一次新运行，保留相同实际输入前缀以形成配对；较长预算的耗时不能用截断样本假造较短预算的耗时。

## 三、为何暂定 128 次，而不是把预实验外推当作保证

独立预算预实验只有四次重复，324 个函数—工作流—预算单元中，242 个提供了原来的粗略重复数外推；其余 82 个分别涉及未认证积分参考 63、L2 未定参考 9、失败重复 4、经验常量／零损失 6。242 个外推中 189 个不超过 128。这些单元相互依赖，该比例不是正式结果达标概率。

原公式以四个非负平方误差的样本均值和标准差计算 `ceil((1.96 × sd / (0.25 × mean))²)`。对于 m 个非负数，样本变异系数至多 √m；m=4 时，该公式的最大值必然为 **246**。因此“所有外推都不超过 256”主要受数学上限约束，不能证明 256 次足够。

本稿选择 128 是一个有限、透明的设计折中：在单个工作流—目标—预算单元的独立同分布二项模型下，若观察到 0/128 次失败，双侧 95% Clopper–Pearson 区间上限约 **2.84%**；若失败率在一半附近，区间宽度约 0.179。这个分辨率不等于整个研究同时覆盖，也不保证均方误差的相对精度。区间算法见 [SciPy 1.15.3 文档](https://docs.scipy.org/doc/scipy-1.15.3/reference/generated/scipy.stats._result_classes.BinomTestResult.proportion_ci.html)。

| 每组重复数 | 全网格拟合数 | 主要数组逻辑容量（GiB） | 零失败时双侧 95% 上限 |
|---:|---:|---:|---:|
| 32 | 10,368 | 93.59 | 10.89% |
| 64 | 20,736 | 187.18 | 5.60% |
| 128（草案选择） | 41,472 | 374.35 | 2.84% |
| 256 | 82,944 | 748.71 | 1.43% |

扩大至 256 会使任务与主要存储翻倍，在常规方差近似下标准误仅缩至约 0.707 倍。另一个审查选项是顺序基线 128 次、其他执行器 32 次；它会缩减逐执行器失败／成本证据，因此本稿暂不采用。若资源实测迫使改变设计，应在采样前产生新草案及协议身份，而非静默减少某些工作流。

## 四、输入、停止和有效性契约

新 `formal_inputs.py` 使用实验身份、目标、重复、角色、链的显式地址，按角色／链建立独立 Philox 流。旧 `目标索引×100＋重复号` 在 128 次时只有 928 个不同地址对应 1152 个目标—重复组合；例如 L1/100 与 L2/0 会重叠。新规则不改变历史四次预实验。正式输入需保存实际初值、噪声、均匀数、求解方向及哈希；NUTS 同时保存每链种子与实际随机状态，没有与 MH 同路径的声明。

当前单元检查在九目标、256 次、四链、五角色下核对 46,080 个地址和 SeedSequence 键以及 9,216 个 NUTS 种子没有重复。它是有限地址检查，不是数学独立性证明。正式输入还须用最终实验身份重新完整生成、核对、封存；目前测试数组不能充当正式输入包。

Picard 的 `max_iter` 是整段轨迹的轮次上限，而 quasi-DEER 的上限作用于每个窗口。统一设置 2048 会在最长轨迹 16,896 步时人为要求 Picard 平均每轮至少确认约 8.25 步。本稿改为：Picard 上限为该任务 MH 总步数，每个成功轮次至少确认一步，否则按无进展失败；quasi-DEER 每窗口上限仍为 2048。这是新协议的预定规则，不回改历史限制，不在失败后临时延长。

每份 MH 长路径都独立重放完整 NumPy 递推，保留接受事件、自环、残差、停止原因、数值修复、前缀和回退成本。H1 已有失败保持隔离；同前态局部一致或短路径通过不能替代完整路径要求。NUTS 采用自己的完整输出、变换、进程恢复及诊断标准；它没有独立 NumPy 全路径 oracle，不套用 MH 接受事件声明。

数值有效、统计探索和估计误差是不同状态。发散、低 ESS、较大 Rhat 或常量事件仍报告；不能把不利但有限的诊断删成“失败样本”以改善误差。违反明确数值输出标准的轨迹则不得成为普通样本。

## 五、估计量、参考和区间

沿用独立预实验锁定的 36 个原参数函数及尺度，不用正式样本方差重新归一化。逐函数展示是主要分析；同目标最大误差只对明确列出的合格函数子集计算，须同时显示全函数集是否完整，不作跨模型的统一排名。

| 参考类别 | 可报告的量 | 必须保留的限制 |
|---|---|---|
| G1/G2/A1/H1/H2/M1 解析期望 | 相对于真值的均方误差 | 只覆盖已列函数，诊断仍单独报告 |
| L1/L2 合格有限 MCMC 参考 | 相对于有限参考点的平方偏差 | 报参考 MCSE；不能直接改名为真实 MSE |
| W1 数值积分 | 相对于指定积分结果的平方偏差 | 网格／尾部证据不等于认证总误差界 |
| L2 未定符号事件 | 观测估计、事件数、诊断 | 误差、标准误和误差区间为 null，不填零 |

已生成新的 L2 伴随解释：原九行的观测零事件保留，但参考未定时误差字段不可用。原 CSV 和协议不改写。W1 稀有事件全零也不能解释为其估计不确定性已知为零。

每工作流误差首先以数值有效输出为条件，列出计划数、有效数、失败数和原因；存在失败时，不把成功者平均值称为无条件全任务误差。两工作流的误差差只在共同有效重复上配对，并报告 `n11/n10/n01/n00` 四格表；明确它条件于两者均有效，不能从各自不同成功样本集合直接作配对比较。

拟采用 9,999 次整体重复重采样、双侧 95% BCa 区间。每个目标内同一组重复索引同时作用于全部预算、方法、函数、有效标记和成本，leave-one-out 也删除完整重复；不独立重采样链、抽样步或不同方法。共享的有限参考值在外层重采样中固定，因此区间条件于该参考。至少 20 个合格／共同合格重复才计算该条件区间；经验损失常量、jackknife/BCa 退化或任何必要分母为零时，区间不可判定并保留原因，不退回零宽区间或悄悄换法。此摘要层算法现已实现，并通过独立SciPy对照和保存预实验摘要核验，见[实现报告](FORMAL-UNCERTAINTY.md)；正式原始数组流式分析及全流程验收仍待完成。[SciPy 的 bootstrap 文档](https://docs.scipy.org/doc/scipy-1.15.3/reference/generated/scipy.stats.bootstrap.html)说明配对索引和 BCa 退化情况。

有限参考的 ±2 MCSE 只作为共享参考移动的敏感性分析；不是偏差界、真实均值置信集或已传播参考不确定性的 CI。应对全部配对差应用同一参考移动。未认证积分另列网格敏感性，不套用不存在的 MCSE。

区间为逐项描述性区间：324 个工作流—目标—预算单元、1296 个函数单元，不声称同时覆盖、不据显著性筛选赢家。主要成对比较事先限定为同设备／同核的顺序与时间执行、以及 CPU NUTS 对各完整 MH 工作流；跨设备结果另组解释。成本报告成功条件分布及所有计划任务的资源消耗，失败任务已付成本不能消失。失败率使用计划分母和二项区间；基础设施中断与科学失败分开计数。

诊断从完整保存数组计算 rank-normalized/folded Rhat、bulk/tail ESS、链间／链内特征及可获得的 NUTS 发散。函数误差小但探索诊断不利时两者并列，不提升为整体后验可靠。报告固定预算结果；不将四点插值称为精确达到精度所需时间。

## 六、执行资源、计时与恢复

完整逻辑数组按九目标维度和为 180、函数数为 36 计算。128 次时实际输入约 23.78 GiB、MH 双坐标路径约 261.56 GiB、接受数组约 1.63 GiB、NUTS 路径及预热约 32.70 GiB、步长轨迹约 0.89 GiB、R 函数二进制及回写约 53.79 GiB。合计约 374.35 GiB，**不是压缩后磁盘预测**；不含 JSON 逐轮日志、独立核验工作区、失败部分输出、归档和解压副本。

正式 MH 计划共约 8.78 亿链转移，NUTS 约 1.19 亿链更新；后者不是 leapfrog 次数。不能由 Mac 秒数直接推算 Windows 总时长。Windows Codex 应在启动前检查实际磁盘余量、写入能力和 CPU/CUDA 内存；还需对最大任务做非正式技术验收以记录峰值与输出大小。只允许因此修订存储／实施方案，科学网格变化另立版本。

历史分析器会同时保留所有输入，以及不同重复的最新预算路径；完整网格仅这两项就约 23.78＋104.06 GiB，超出 Mac 16 GB，也不能假定 Windows 足够。正式分析必须按目标—重复处理，一次读取一个任务，前缀比较按需读取同组邻近预算，及时释放数组；R 诊断使用有界批次，最终只聚合标量结果。采样器 2 GiB 数组估算不是进程峰值内存保证；父进程、worker、CUDA、分析器须分别监测。

计时需要不重叠的阶段日志：进程／导入与模型建立、输入读取与传输、适应或丢弃、采样、变换与普通诊断、独立参考核验、证据写盘与压缩、哈希和终态提交。CUDA 阶段边界显式同步；NUTS 以父进程池墙钟计总体，不把并行 worker 的时长求和称墙钟。固定几何与调参的预付开发成本单列来源，不隐记为零。

同时报告缓存执行、正常推断所需阶段的小计和完整研究审计流程。若正常小计来自同一审计运行的阶段求和，应明确其测量方式；它不等于另一次独立测得的冷启动普通用户流程。已有 pilot 的 task wall 截止于部分归档之前，且 R 诊断另跑，因此不得改称已覆盖完整普通或审计成本。

任务在预定重复块内交错安排 CPU、CUDA 与 NUTS；顺序用独立调度流冻结，不按运行快慢调整。通过全机统一位置的互斥锁避免两个实验目录同时争用设备。记录父子进程线程设置、CPU 时间、设备信息、显存／内存和外部负载；四线程与四进程不等于完全相同的物理资源利用。

每个任务结束原子登记和校验，恢复只跳过身份、源版本、输入和资产均匹配的终态。当前目标是任务级恢复，不承诺中途 sampler checkpoint。数值失败不重试；基础设施中断保留原尝试，原因明确时允许最多一次同身份重跑，重跑仍失败则保持未解决终态并继续其他任务。不能重试到通过。

磁盘不足在新任务边界进入资源等待，保留专用失败日志余量；这不是总实验时长上限，也不作为科学失败。启动门槛、每任务检查公式及中断恢复行为须在实际运行器中实现，不能只写在文档中。

2026-10-05成本补记：以上普通/审计墙钟已由独立子进程及外层账本实现；[FORMAL-COST-POLICY](FORMAL-COST-POLICY.md)定义跨尝试归并、失败/未知时间和逐函数误差—成本的一致框架。含审计调用不包括记录器自身写盘、批次归档及传输；这些另列，不能把嵌套阶段机械相加称全部端到端成本。全部数值有效输出与某函数可用输出集合可能不同；主误差—成本点必须按该函数同一集合计算，任何集合内缺失成本均保留不可用。当前缓存技术证据不自动成为正式缓存任务安排，最终协议仍待冻结。

### 缓存伴随与批次费用的v0.2补充

已实现的[正式测量设计](FORMAL-MEASUREMENT-DESIGN.md)在每目标每批32重复中预选8个，共32个原输入；所有预算和MH配对共享选择，合计9,216探测任务，每项初始执行＋3次重放。安排不读取主任务结果，失败配置不换样；NUTS保留完整流程口径。探测在主批次终态/已明确保留中断且无遗留进程后单独执行，不计入主任务普通成本，也不增加独立n。

缓存伴随只作同核执行比较，以这32个原重复为框架，独立保存并跨全部缓存方法/预算共享整体BCa索引；不将三次技术重放变成96次独立重复。主误差—成本分析仍用128重复及原同函数可用集；不得把32次缓存时间配128次误差。缓存跨重复统计及真实CPU回执已完成[有限集成核验](CACHE-PROBE-EXECUTION.md)，原生调度中的测量任务类型与Windows运行门槛仍待完成。
