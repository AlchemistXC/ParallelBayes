# 正式测量设计：缓存探测分配与批次费用

2026-10-05；分配/费用/核验源码 `960e983`，归档重建 `d545247`。使用已约定任务/测量接口的TDD、codebase-design，以及nature-statistics检查重复单位、选择条件和失败框架。本轮实现及核验的是**前瞻测量设计和记录接口**，没有冻结正式推断协议，没有启动正式采样或Windows计时。

## 已具体化的安排

主研究仍是九目标×四预算×九工作流×128次四链重复，共41,472拟合。普通推断与研究审计成本记录全部主任务。缓存伴随测量另外登记，不放进主任务的普通耗时，也不把重放输出当新样本。

| 设计项 | 本版决定 |
|---|---|
| 输入选择 | 每目标、每批32重复中预选8个；四批合计每目标32个 |
| 选择规则 | 对实验身份、目标、批号、重复号作域分离SHA256排名；同目标/重复的所有预算、核、设备共享选择；不读取任何结果 |
| 对应工作流 | CPU/CUDA各四种MH组合，覆盖四预算，共9,216探测任务 |
| 每个探测 | 一次初始执行＋三次准备后重放；总36,864次内核执行，但新增独立统计重复0 |
| 顺序 | 主批次已终态或中断被明确保留、且原生进程集合确认无遗留后，单独执行本批探测；域分离顺序交错全部被选任务 |
| 数值条件 | 每次都按最终协议实际数组、目标、配置及独立路径/事件标准核验；初次和三次重放全部满足才能形成缓存成本点 |
| 单输入摘要 | 三次准备后执行时间的中位数，不取最快值；任一执行失败/未运行/缺记录则该点不可用，保留全部已知消耗 |
| NUTS | 不定义缓存NUTS指标，仍报告四进程完整普通/审计流程 |

使用`create_measurement_plan(identity, primary_tasks, batch_size=32, selected_per_batch=8, replays=3)`生成完整计划，再以`validate_measurement_plan()`从原网格重建核对。它验证任务身份和实际输入文件名、完整同核顺序/时间配对、各重复的完整配置，以及不受输入行顺序影响的选择。该接口不生成实际随机数组，不授权正式执行。最终实验身份未定，因此当前分配只是可重建草案；最终身份确定后须在观察结果前生成并冻结对应表。

每个被选输入必须保留全部对应工作流，即使原主任务数值失败、全拒绝或很慢也不能换输入。探测自己的合格输出不回填或挽救失败主任务。资源拒绝和中断按原生运行政策记录，未执行重放明确缺失；不要为凑齐“成功三次”反复运行。现有冻结`cached_cost_worker.py`只接受历史Mac技术profile且要求原任务有效，**不能直接作为正式worker**；后继执行器须去除这种结果驱动的任务入选条件，同时保留原文件。

已有`PreparedExecutor`界定内核墙钟：预先同步后开始，到执行完成并同步后结束，含分配、原Python控制和求解遥测；准备、传输、变换、独立核验及归档另记。当前是torch eager，首次调用并不自动等于编译耗时。逐次审计/写盘与重放之间的间隔会影响热状态，应记录；三次重放不能证明达到硬件热稳态。

## 统计分析边界

主推断分析仍以128次完整四链拟合为每格计划单位，原正式草案的整体重采样规则不变。缓存是每目标预选32个原始重复上的**伴随同核成本分析**；全部方法和预算共享这32个重复ID，不把三次重放变成96个独立样本，也不宣称又获得32个新后验重复。

缓存条件费用比使用两方法共同合格的被选重复，报告32个计划输入的可用/失败/缺失四格表。拟用独立保存的“缓存伴随”整体重采样索引，在所有缓存方法/预算中共享，9,999次逐项95% BCa；至少20共同可用重复且非退化才报告区间。这个重采样框架与主推断128次的框架明确区分，不能将其索引数组混用或将两种区间视为独立证据。2026-10-06后继：[缓存跨重复统计接口](CACHE-PROBE-ANALYSIS.md)已用人工完整帧、错误注入和独立SciPy对照核验；正式worker与实际回执衔接仍待完成，没有生成研究区间。

普通工作流的误差—成本图用原128重复框架及同函数可用集。缓存中位时间只用于执行机制比较，不直接替换该图的完整推断成本，不拿32次时间与128次误差拼成同一测量点。BCa不保证32次精度足够，时间漂移与外部负载也不由固定顺序自动消除。

## 资源代价必须预先公开

该安排增加36,864次MH内核执行，恰好相当于主网格MH执行数，但无新增推断样本。保留每次无约束路径与接受数组的逻辑容量约**131.60 GiB**；不含逐轮JSON、审计、压缩/解压副本、失败部分输出或其他缓存。与原主设计374.35 GiB相加约505.95 GiB，仍不是实际磁盘需求预测。无需复制主随机输入包给每个探测，按已冻结文件哈希引用它。

选择32输入是有限的事前测量折中，不保证任何统计精度或运行时长。Windows必须根据实际最大任务与磁盘证据再决定实施可行性；资源不足时在正式采样前产生新设计身份，不能事后只减掉慢配置或困难目标。没有人为总实验时间上限。

## 批次费用接口

`BatchCostLedger`接收明确的研究身份、设计SHA256和预声明操作列表。准备输入发生在正式输入哈希冻结前，故绑定事先确定的设计身份；最终协议应引用该设计及其已生成输入回执，避免循环定义。

支持准备、归档、传输和核验四类阶段，每个操作ID只记录一次。调用前先写开始回执，结束时保存实际墙钟、成功/失败和小型结果校验信息。操作异常保留后重新抛出；重复调用拒绝，不能自动重做未封存工作。后续明确的尝试须有单独登记，接口本身不授予重试许可。

计时包围操作本身，包括它实际等待的子进程；不含账本写盘、重新打开/报告/重复检查、操作间空闲及未登记活动。费用保持批次级，不任意平均摊到单拟合。未开始和缺结束回执分别标记；二者都不能补成完整耗时0。已失败但有结束回执的费用仍计入已知消耗。报告不根据时间戳推断丢失耗时，也不根据回执缺失推断进程已死。

通过同一原生主机锁串行化合作测量，但调用者仍负责实际进程集合和资源安全。它不能替代Windows Job Objects/恢复保护，原生Windows行为尚待验收。为避免嵌套加总，阶段记录不再加到已包含它的采样调用；本接口只用于主任务计时外的批次工作。

## 本次实证核验

4项新增行为检查与6项受影响检查通过（合计10项）。其中实际子进程用退出码7模拟记录器在操作中终止，后续核验成功后，原操作耗时仍未知；这只是明确位置的故障夹具，不是任意进程树恢复证明。最初误从暂存路径运行测试造成导入失败，其日志保留；工作树测试确认接口缺失红灯后实现，最终通过。中断附加检查首次即通过，未人为制造失败。

完整草案重新生成41,472主任务、9,216探测、每目标32个选择；未生成正式随机数组。另对既有缓存证据327项资产核对哈希，复制16份已核验执行记录及对应数组，实际进行本地打包、同文件系统复制、逐成员核验，并搬移费用账本。四阶段有真实费用回执，但这里的“传输”仅为**本地文件复制**，不是网络传输性能。操作时间总计约0.0836秒，只说明该小型I/O夹具被计量，不能预测正式Windows准备/归档费用。

四份缓存中位数从16个历史时间记录重建一致；没有调用MCMC、重新运行独立NumPy参考或新增计时内核。已验证的是保存资产/归并，数值正确性沿用其原冻结技术核验。79个最大批次冻结数值文件哈希不变。
