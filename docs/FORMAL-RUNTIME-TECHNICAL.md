## 计时和恢复边界

主机锁只约束使用同一绝对锁路径的合作运行器，不能排除其他应用。已有完成／数值或资源失败的终态可在身份与所有资产哈希一致时恢复；**中断任务尚无自动分类和重试实现**，目前明确拒绝恢复，需后续独立记录处理。

外层回执分别记录准备、工作进程生命周期、资产哈希及终态写入；另给出从准备到终态写入的包含成本。最终回执自身的哈希／写入不在该边界内。子进程记录导入、输入、目标、采样、归档和 R 诊断的互斥阶段，阶段日志写入及间隙不属于阶段和。采样器内部嵌套计时不能再次加到外层墙钟。

**缓存执行和正常推断工作流尚未在此运行器分别实测**；当前 MH 执行包括完整独立参考审计，不能把去掉某个计时字段后的差值当作已经测得的正常用户成本。

## 归档与复用

Git 中的紧凑证据位于 `benchmark/analysis/outputs/formal-runtime-technical-v1/`；技术协议位于 `benchmark/protocols/formal-runtime-technical-mac-v1.json`。完整本地包是 `formal-runtime-technical-v1.tar`，55,603,200字节，SHA256：

```text
912a6a4489f4c84be96846df7ac32a8f56459ab818f60719fca1d294955de7ee
```

包内230个文件逐项核验，包含源码快照 `source.tar`、实际随机数组、全部10任务原始输出、恢复和内存样例、环境清单及红绿灯日志。没有自动公开 Release。归档校验不是干净环境安装或全论文复现。

从独立目录解包并再解开 `source.tar` 后，可用匹配依赖的原生 Mac Python、R 和 R 包环境运行：

```text
python scripts/completion/formal_runtime_validation.py run --protocol ../formal-runtime-technical-protocol-v1.json --inputs ../formal-runtime-technical-inputs-v1 --output NEW_OUTPUT --rscript /absolute/path/to/Rscript --r-library /absolute/path/to/R-library --host-lock /absolute/shared/host.lock
```

必须选择新输出目录，使用同一个合作主机锁。原归档任务的请求包含原环境绝对路径；异目录重放是新技术执行，不声称可以直接接续旧任务，也不增加独立统计样本量。

## 到正式启动还缺什么

1. 中断识别、明确重试身份、磁盘写满／资源失败分类与保留规则；不能把资源失败混入数值失配而不区分。
2. 从原始路径逐任务提取函数、诊断和成本的流式分析，并衔接已核验的配对不确定性接口；当前技术脚本只覆盖两目标，不能直接放大全缓存。
3. 独立的缓存、正常推断、研究审计测量方案及全过程成本核验，避免嵌套重复计时。
4. Windows实际 F1/F2/F4、MH和NUTS回执，以及最大任务的内存、磁盘、原生进程／主机锁实测。
5. 上述门槛通过后，最终确定有限实验网格，冻结正式协议、实际输入与依赖，再执行正式推断比较。41,472拟合仅为现有草案规模，不是本次启动指令。

F5的两平台干净安装／完整归档重建和F6的论文整合仍未完成；本技术工作不替代任何一项。
