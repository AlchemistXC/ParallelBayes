## 本次接通的接口

`formal_evidence.RuntimeEvidence`读取固定哈希的SQLite登记快照和明确的原输出身份→归档相对路径映射，逐任务核对登记事件、尝试顺序、终态、恢复关系和资产。它不读取原机器的进程状态，不执行恢复，不修改登记；原绝对路径只是历史身份。人工核验中删除原目录和工作程序后，搬迁副本仍可正常读取。未解决的登记进程仍被拒绝，不能用分析程序猜测其已经停止。

`formal_runtime_analysis.extract_task`先取得经核验的尝试历史，只从最终有效尝试中取普通样本。它分别核对模型、科学任务/协议、保存核配置、实际输入数组和MH输入前缀；检查保存的独立审计记录，或CPU spawn NUTS的初值、实际种子、预热和链记录。随后复用有界逐任务读取，验证原参数变换、生成函数估计和R二进制传输。它核对已有审计证据，不冒充重新执行了每条NumPy递推。

`aggregate_records`在一个模型的标量层连接既有配对不确定性与全部尝试成本接口。每个计划的工作流×预算×重复均须有一条记录；失败、未运行和不可用函数不能被删行。重复单位仍为完整四链任务，多次尝试不增加n。函数是否可用、参考是否合格、轨迹输出是否合格、总耗时是否完整分别处理。原尝试耗时未知时，总成本及相应配对比值保持不可用；已知部分仍进入资源消耗总数。

这个接口适配的是当前登记与runtime-v1证据格式。未来正式协议和批次驱动尚未冻结，不能把有限格式衔接当作全规模正式实验已经就绪。

## 检查、错误注入与修订

最终新增4项公开接口检查通过：只读搬迁与身份/损坏拒绝；恢复链搬迁与原成本保留；有效/失败数组区分及目标/核配置检查；完整重复框架下的资源失败、未运行、未知恢复成本及未定参考。受影响的流式读取2项和成本3项也通过，共9项，重复运行不累计成新测试。

人工汇总样例同时包含已知中断后成功、资源失败、未知中断后成功、未运行任务。手工设定的21秒已知消耗仍完整保留，其中4秒属于总成本未知的任务；没有将未知部分补零，没有删除计划重复，也没有为未定参考输出零误差。这些数字是测试预期，不是实测采样性能。

补充错误注入发现：调用者给出的任务标签与核配置彼此矛盾时，初版仍可能通过各自的局部一致性检查。红灯样例以MALA任务声明搭配RWM配置，修订后被拒绝；NUTS也明确限定为当前已支持的CPU spawn提供方式。初次目录布置还触发了分析输出不得位于证据内部的保护，修正的是人工测试目录，没有放松保护。红灯与最终日志均保存。恢复搬迁扩展检查直接通过，不虚构先失败记录。
