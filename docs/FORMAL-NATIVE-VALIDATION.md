## 固定范围与命令

入口为 `scripts/windows/validate_formal_adapter.py`。`prepare`、`test`、`run`、`seal` 均在非 Windows 平台写入输出前拒绝；`verify` 与 `export` 为可搬移的只读核验/归档操作。

| 命令 | 产物及条件 |
|---|---|
| `prepare` | 独立身份 `windows-formal-adapter-validation-v1`；G1/W1 各 576 步输入、G2 16,896 步输入，均四链；实际数组、原始地址、源码/三份测试源码、外部水井八文件、环境及锁文件在采样前封存 |
| `test` | 原生 pytest 的 16 个行为用例，外层 ancillary Job 管理 pytest 及后代，共享主机锁；XML、命令、Job 观察、全部测试夹具保留 |
| `run --phase main` | 三目标各九工作流，共 27 主任务；使用新 v2 运行器和正式 worker；G2 保留每链 16,384 步 |
| `run --phase cache` | 主阶段全部结束后运行预声明 24 探测；每项一次初始与三次准备后调用，共 96 次；没有普通后验样本资格 |
| `run --verify-only --phase ...` | 要求所有任务已登记且有结束尝试；核验原件和账本，零新执行；核对全部原任务文件未变 |
| `seal` | 核对实际行为测试、51 任务各自唯一的合格尝试和核验调用后才生成 `native-acceptance.json`；失败/中断不能获得验收 |
| `verify`、`export` | 搬移读取验收资料并输出带完整清单的 tar、整体 SHA256 和导出耗时；归档与既有 `verify-windows-return.py` 格式相容 |

普通工作流、含审计的外层调用和额外核验分别记录，嵌套时间不相加。阶段主体计时不含预检查及最终报告写入；输入循环计时不含此前环境/快照准备，均不改称完整冷启动总耗时。测试的进程等待限时只用于人工夹具就绪判断，科学任务没有新增总时长限制。

正式数值设置改为由 `study_controls()` 提供，所有设置值与 `466605e` 逐项相同；正式计划的任务数、模型、预算、容差和成本政策均未改。采样包、正式 worker、原生 Job API、v2 运行器和所有历史协议/结果未变。

## 失败、恢复与封存

输入准备仅在源码、环境和地址一致时允许显式 `--resume`；不重新调用已封存输入的 RNG。未封存的单文件失败须指定 `--recover-input` 和原因，保留旧原件后再处理。完整或部分协议封存不覆盖。

主/缓存阶段 `--resume` 仅核验已结束任务并继续未启动任务。本轮有限验收不提供采样重试选项；数值失败、资源失败和中断均保留，也不会因为它们而另选输入。它们可完成描述性任务框架，但不能通过验收。需要兼容性修订时，在新提交和新目录产生不同源码/协议绑定，旧失败包仍回传，不能抹除后重称首次成功。

行为测试再次运行须给出明确 `--repeat-reason`，旧测试目录保留；对原命令的 Job 做实际 Windows 观察。源码或依赖变化会要求新冻结目录。只读接收同时检查 XML、实际命令/源码、Job 终态和调用账本，不能只凭 `passed=true`。

驱动锁放在证据目录之外，避免释放锁时更新 owner 记录而破坏验收文件清单。封存后只允许读验收/导出；已封存数据不再添加采样或核验调用。
