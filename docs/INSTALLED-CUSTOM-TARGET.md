## 实际核验

| 项目 | 结果 |
|---|---|
| 实际输入 | 一份四链×128步×二维输入，两个提供方式、两个语言入口共用原文件 |
| 数值工作流 | 16/16 完成独立审计；不是16份独立统计重复 |
| 同提供方式、同核顺序/时间配对 | 8/8 通过原数值标准，接受事件零失配 |
| Python/R同提供方式对照 | 8/8路径及事件逐字节相同 |
| R原数组回写 | 8/8 float64小端数组与保存样本逐字节一致 |
| torch/JAX对照 | 4/4接受事件相同；最大状态差9.058×10⁻¹¹，小于本输入2×10⁻⁸门槛 |
| 错误与保护行为 | 不支持核/执行器、已有输出、损坏输入均拒绝；人为参考梯度错误被发现并隔离 |

torch 点核验最大相对密度差1.422×10⁻¹⁴、梯度差7.106×10⁻¹⁵；梯度中心差分
HVP对照最大差6.465×10⁻⁸。后者是固定有限差分检查，不能称完整转移映射导数证明。
同核配对最大路径差1.077×10⁻¹⁰；没有放宽原 `atol/rtol` 或接受事件标准。

人为梯度错误产生30处接受事件失配，结果为 failed，普通样本为空，失败路径和审计保留。
该注入额外执行一次顺序 MALA；合计17次技术数值调用，新增正式研究重复数为0。
四项行为检查独立留档，不累加到历史采样器或 R CMD check 的通过数。

16个保存的参数诊断全部有有限 Rhat>1.01，范围1.019–1.117；无不可判定Rhat。
bulk/tail ESS和完整诊断保留。它们来自短运行且包括重复语言执行，不能合并为独立收敛证据。
未用这些计时作性能比较，没有宣称推断或CPU/CUDA收益。
