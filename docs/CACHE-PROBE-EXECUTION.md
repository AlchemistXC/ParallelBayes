# 缓存实际执行到统计接收的本机核验

2026-10-06。数值/记录接口`c745745`；显式源码预检修订`2f9956b`。使用tdd及codebase-design，在已约定的实际输入、输出、费用和统计接口工作。本轮执行真实CPU短路径；**不是正式推断研究，也不是Windows进程管理验收**。

## 新接口及其能力

`cache_probe_execution.execute_cached_probe(capsule, capsule_sha256, probe, inputs, output)`将冻结任务配置和事前分配的探测对应起来，核对源码、依赖、目标、实际输入文件与数组哈希，执行一次初始调用和三次准备后重放。它没有读取成功主拟合的入口，不会按主拟合结果筛选入选配置。

每次保留实际无约束路径、接受事件、求解遥测和同步后的执行/传输时间，随后独立NumPy重放核验。准备、归档、独立审计另外记录；嵌套耗时不机械相加。迭代失败照常保留四次预定记录，不反复重试到成功。准备资源拒绝时后续槽位未运行，缺执行时间保持未知。

产物类型固定为`cache_measurement`，`samples_eligible`始终为false；`measurement_available`表示该探测记录是否完整且通过输出核验。缓存统计可读这些记录，后验样本入口不能接收。只读`read_cached_probe()`核对封存清单、逐次回执、原始数组形状/哈希与摘要；不重采样，也不重新运行独立参考。已有输出目录拒绝再次执行。

这是数值/记录模块。当前执行入口只接受原生Mac CPU技术协议，调用者仍负责主机互斥、进程生命周期和资源监督。旧`formal_runtime.execute_task`把完成状态和后验样本有效性绑定，**不能直接用它管理本模块，更不能将缓存的samples_eligible改成true来适配**。原生调度需明确区分测量任务与推断任务；本轮没有改写冻结旧调度器。

## 检查及一个修复

新增7项检查（含四种工作流参数化实例）与8项受影响检查通过，共15项、0失败、0跳过；日志含18条torch.jit.script弃用警告，未据此改用未验证编译后端。

覆盖真实RWM/MALA顺序和时间执行、没有主拟合时的独立核验、迭代耗尽、准备内存估算拒绝、实际输入变更拒绝、搬移/损坏检测，以及输出目录不覆盖。故障检查仅在存储边界注入OSError，数值内核和时钟未被替换。

该检查揭示并修复了：执行已返回但后续归档失败时，已测执行耗时被遗漏。现保留这笔费用及基础设施错误；没有归档的路径保持不可用，剩余重放标为未运行。此修复不证明任意强制终止或整机崩溃都能恢复全部耗时；未写出的时间仍可能未知。
