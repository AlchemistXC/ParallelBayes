# F3：推断比较的开发门槛与后续设计

2026-10-05。当前阶段是目标、坐标和成熟基线的就绪验证；正式调参、预算探测和推断实验尚未完成。原Mac及Windows-v1所有协议、39份科学源码和负结果保持不变。

## 为什么先补这一步

原torch MH支持逐链初值和显式Model，但原Pyro包装器固定零初值并只接受内置spec。新伴随入口`scripts/completion/inference_nuts.py`接收明确的CPU torch Model和逐链初值，仍使用Pyro NUTS，没有重写NUTS算法。它保留预热状态、适应后的步长/质量矩阵、原始随机状态、部分失败轨迹及Pyro诊断；调用结束恢复宿主的Python/NumPy/torch随机状态。

依据[Pyro MCMC文档](https://docs.pyro.ai/en/stable/mcmc.html)和本地1.9.2实现核对`potential_fn`、`initial_params`、hook及质量矩阵接口。当前伴随入口逐链串行，不宣称多进程或GPU NUTS。Pyro公开诊断未提供完整树深命中计数，记录为未提供而非零。正式同资源比较仍需核验合理的CPU链并发方式，或明确串行基线的资源与适用边界，不能用此就绪验证假定该问题已解决。

## 固定坐标与目标

新`examples/affine_target.py`实现q=c+Lz，并在z空间使用log p(c+Lz)+log|det L|；原参数输出仍通过原模型的constrain。NumPy参考按链式法则独立计算梯度，torch用自动微分。模型身份保留原目标ID和完整固定矩阵。它不支持任意Stan转译，也不是新概率语言。

`inference_setup.py`只从目标参数/密度导数构造固定几何，不读取后验参考样本。高斯使用已知曲率；正态先验logistic和水井目标用数值模式处的解析观测信息。优化状态、梯度残差、条件数和构造成本保留；失败不静默改成单位矩阵，不修补非正特征值。漏斗和混合目标采用明确的单位坐标。Laplace在这里是提议坐标选择，不是评价采样准确性的真值。

固定预条件改变了原坐标下的MH核。因此不能拿新预条件轨迹与历史未预条件轨迹声称“同一核加速”。新同核比较必须共享几何、核参数、初值和实际随机数组；原参数上的推断量保持一致。

## 首批就绪验证：inference-readiness-mac-v1／v2

- 目标：G1、G2、A1、L1、L2、H1、H2、M1及外部W1水井，共9个。
- G2/A1/L1/L2/W1采用固定Laplace几何，其余单位几何。每目标2条链；实际初值从选定坐标中的N(0,4I)产生并保存，M1首坐标预设为-5和+5以覆盖两侧。此初始化不保证模式间混合。
- 每目标四个MH工作流，每链64步、窗口8；共同实际噪声、对数均匀数及JVP方向。通用尺度RWM=1/sqrt(d)、MALA=0.1/d^(1/3)，未经优化，不作为正式调参结果。
- 每目标一份CPU NUTS工作流：每链256步预热、256步保留值，目标接受率0.8、对角质量适应、最大树深8。两条链不是两次完整实验重复。
- 各目标只有一次开发性运行。总计45个计划工作流；状态为完成仅表示各自输出标准通过，不等于统计校准或收敛。MH有独立NumPy轨迹核验；NUTS没有同一MH路径声明。
- 固定Mac CPU、torch线程1；新`.venv-inference`采用Pyro1.9.2、torch2.13.0、NumPy2.2.6、SciPy1.15.3。第一次安装过1.9.1，随后在任何采样前对齐1.9.2，两个日志均保留。未修改已有`.venv-completion`或Windows冻结环境。
- 数值/数组内存守卫、源码/协议检查、逐目标原子终态、OS互斥锁和严格恢复；不设总实验时间截止。失败及中断尝试保留，目标失败不阻断其他目标。

## 后续仍必须完成

1. 独立调参开发：预先确定有限的步长/预热候选与选择规则，保留全部候选、失败及调参成本。不得根据正式误差选择步长，也不以接受率或短链ESS代替混合评估。
2. 独立预算pilot：与开发性调参分开实际随机输入，观察多个预算的函数误差、链间诊断和成本，用事先确定的区间精度目标规划正式重复数。当前就绪验证不提供重复方差。
3. 固定评价契约：保留既有函数并明确新案例函数；在原参数尺度定义误差尺度、阈值和参考不确定性。L2常量事件继续未确定；水井数值积分的网格稳定性不能写成认证总误差。
4. 冻结正式协议：模型、几何、初始化、调参规则、预热、核参数、预算点、重复数、CPU链资源、时间窗口、失败规则和计时口径全部固定。不同预算可共享前缀，但统计比较按独立完整重复聚类；计时重放不增加n。
5. 运行新CPU/CUDA MH及成熟基线，报告重复误差与不确定性、现代诊断、失败/未达标区域和完整成本。跨后端/设备只作完整工作流比较。某些估计量达标不能代替后验整体探索判断。

正式数据不得用于继续开发选择器后再当作留出验证。F3完成要求是研究问题得到有边界的回答，并不要求发现正的推断收益。

## 首次实测发现与v2修复

v1（源码d1b5a7c）实际完成了全部9个目标尝试，其中8个目标输出隔离、1个目标完成。失败集中在新仿射层的NumPy批量矩阵乘法：保存的G1有限64×8数组最大绝对值仅3.236，与单位矩阵相乘仍在严格浮点模式触发异常；该数组的显式einsum恒等变换逐字节正确。回归样例保存在benchmark/fixtures/affine-coordinate-v1，首次失败日志和原始采样输出全部保留，不提升为正常样本。

[NumPy上游M4问题报告](https://github.com/numpy/numpy/issues/28687)存在同类有限matmul异常；本项目没有独立证明其所有底层成因。v2将新仿射NumPy路径及新logistic信息计算改为显式einsum，保留浮点异常和输出门槛，没有升级或修改冻结NumPy环境。torch目标和历史39份源码不变。新旧规则、初值/随机数组命名空间及预算相同，v2另有源码/协议身份，不能把v1失败从结果中删除。

受影响接口6项检查通过，包括该保存数组、手算坐标/约束、两种时间执行器、自定义NUTS重放及无效输出隔离。它们不等于9目标v2实测已经完成。
