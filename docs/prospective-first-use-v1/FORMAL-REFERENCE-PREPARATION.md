# 正式参考输入的准备状态

本工作根据决议建立候选模型和输入，最终科学协议及 Windows 资格通过后生成正式封存记录。候选输入的参考结果尚未启动。

## 候选模型和数据

分层 logistic 使用 128 组二项结果，组样本数为 5–24，数据由独立随机流 seed 20261122 生成。真实生成参数总体位置 -0.2、尺度 0.9，各组非中心化标准正态。先验为 μ ~ Normal(0,2)、log(τ) ~ Normal(0,1)、z_j ~ Normal(0,1)，组对数优势 μ+τz_j，直接在 log(τ) 空间指定先验。目标包括该空间的完整先验项。

ODE 数据为 Stan example-models 固定提交 e5b7d9e2e9ecc375805c7e49e4a4d4c1882b5e3b 的 Hudson Bay 表，1900–1920 共 21 行。初始数据保存顺序为雪兔、猞猁，数值以千为单位；观测使用对数正态误差。八个参数为 α、β、γ、δ、雪兔初值、猞猁初值和两个观测噪声尺度。每个参数在对数坐标独立服从标准差 0.5 的正态先验，中心依次为 0.55、0.028、0.80、0.024、30、4、0.25、0.25 的对数。先验直接指定在对数坐标。

这些先验及 logistic 合成数据的具体数值是本次实施中选定的候选配置。正式冻结需要与 Windows 目标的先验、变换、观测数据及结果函数逐项核对。

## 参考运行入口

`formal_run.py` 接收模型、候选输入路径、正式封存记录、逐链数据库和 1000/2000/4000/8000 目标步数。封存记录绑定决议、目标源码、运行源码、SQLite 代码、候选 manifest、预检回执及 Windows 资格和容量回执哈希。每次调用都验证依赖、CPU/x64 和冻结的 JAX/BlackJAX/Diffrax 依赖版本。封存记录及两个外部回执尚未生成。

正式运行入口本身已使用独立的合成测试数据和临时测试封存记录完成端到端检查：1000→2000 步续跑与连续 2000 步逐字段一致，重复续跑零新增步数，错链及数据篡改在生成新数据库前被拒绝。首档十链调度也使用同一套临时记录完成验证，并由 R/posterior 生成诊断回执；输入篡改时，调度器在创建运行目录前拒绝。测试的 Windows 与容量记录均为模拟数据。运行命令为 `$PY -B tests/prospective_reference/test_formal_runner.py "$Rscript"`。

正式 ODE 入口另用常规合成 ODE 数据、模拟封存和模拟资格/容量回执完成单链 1000→2000 步跨进程续跑，与独立连续 2000 步的所有块和字段逐字节一致；错链被拒、重复续跑零新增步数。两条运行各有 0 次保留期发散与 0 次最大树深命中。回执和日志位于项目根目录 `output/mac-formal-ode-synthetic-01/`。测试并非真实数据的正式参考链，也不证明真实 ODE 收敛、十链结果或 Windows 资格通过；不得把模拟回执用于正式封存。

同一常规合成 ODE 另完成十链首档调度与 R/posterior 汇总，按 ODE 限制单链串行，每链预热 1024、保留 1000 步。十链均从相同合成初值出发，实际采样初始 key 逐链不同；十个参考数据库分别生成无 WAL 恢复快照。R-hat 最大值 1.00434，保留期发散 0，最低 BFMI 0.873，记录到 1 次最大树深命中。α 和末年雪兔函数的相对 MCSE 分别约 1.87% 和 1.15%；仅是该合成数据的结果。整组 `--resume` 检验十链各新增 0 步。输出见 `output/mac-ode-synthetic-cohort-02/` 与 `output/mac-ode-synthetic-cohort-02-backups/`。这不验证正式分层初值、真实 ODE 后验或 Windows 资格。

另用独立合成数据和随机流生成十条先验中央 80% 的分层初值，八个坐标各自覆盖十层，每链预留四个同层候选。十链首个候选均通过独立 SciPy 密度/梯度预检；以模拟回执串行完成十链各 1000 步，最大 R-hat 1.00271、保留期发散和最大树深命中均为 0，最低 BFMI 0.843，α 和末年雪兔函数相对 MCSE 分别约 1.96% 和 1.20%。十链 `--resume` 各新增 0 步，十份无 WAL 快照的初值哈希与实际分层数组相符，采样初始 key 各不相同。输入、输出和快照依次位于 `output/mac-ode-synthetic-strata-input-01/`、`output/mac-ode-synthetic-strata-cohort-01/`、`output/mac-ode-synthetic-strata-cohort-01-backups/`。该合成演练未启动真实模型或签发正式资格。

`cohort.py` 在正式封存通过时执行每模型十链的第一个 1000 步检查点，logistic 最多两链并发、ODE 单链。每条链单独记录命令、标准输出、标准错误和退出码；有失败时保留已启动任务，并停止派发后续链。十链成功后运行锁定的 R 诊断并记录参考函数 MCSE。该入口要求全新输出目录。后续延长继续由 `formal_run.py` 从对应数据库执行。

当十条链均有成功退出记录时，可使用同一输入、封存及 R 环境通过 `cohort.py ... --resume` 复核或重建首档诊断。入口先核对十条链已提交的完整 0–1000 步及校验和，再对每条链做幂等调用。已有诊断的恢复记录零新增采样。测试还删除一份测试库的第 1000 步，验证入口在运行任何恢复进程前拒绝。出现失败日志、终态不明或不完整诊断目录时，保留现场并先分类；不能通过此入口自动重试可能的数值失败。

`extend_cohort.py` 负责十链共同进入下一档（2000、4000、8000），封存记录绑定该脚本的哈希。它先复核前档诊断、各链完整块、实际初值和身份；前档诊断未通过、精度未定义或精度已经全部达标时均拒绝自动延长。按原并发上限逐链启动，失败时停止派发、保留已启动任务和日志；成功后重新运行完整诊断。每档只能尝试一次，异常或中断后须分类现场，不能直接重复启动。入口需要前述完整研究封存和真实外部回执，不会生成或替代资格证据。正式使用示例为 `"$PY" -B scripts/prospective_reference/extend_cohort.py logistic "$INPUTS" "$SEAL" "$COHORT" --rscript "$RSCRIPT" --steps 2000`；后两档只有前档完成且仍需提高精度时才能运行。

参考链使用 SQLite WAL，不能单独复制运行中或停止后的 `.sqlite` 主文件并假定包含全部已提交数据。`portable_backup.py` 使用 SQLite 备份 API 生成包含 WAL 已提交内容的单文件快照，核查数据库完整性、链身份、块连续性和各块哈希，再以不读取 WAL 的独立副本重开验证；输出新目录、快照哈希和回执。示例：`"$PY" -B scripts/prospective_reference/portable_backup.py "$CHAIN_DB" "$NEW_BACKUP_DIR"`。快照只说明某个一致的已提交检查点可恢复；它不保证十条链处于同一档，也不能替代正式诊断和归档容量核算。出现错误时保留原数据库及 WAL 和失败目录。

合成 ODE 单链的两份 2000 步快照分别来自续跑与连续运行；用相同模型和模拟封存将两份快照各自续至 4000 步后，41 个块中所有保存的状态、随机 key 和诊断字段逐字节一致。测试证据保存在 `output/mac-ode-snapshot-resume-01/`，4000 步结果另有独立 SQLite 快照。该测试不使用真实留出数据，也不构成真实 ODE 的十链精度或资格验收。

`create_freeze.py` 使用已取得的 Windows 资格、资源容量以及对应模型的跨进程续跑回执创建模型专属参考封存记录。两个模型可以分别验收，logistic 的参考封存不依赖 ODE 的模型专属验收。每个模型仍绑定相同的完整研究协议、数据和外部资格条件。程序将回执复制进新的封存目录，以参考入口复核全部哈希和条件，再写出正式封存记录。预检条件不满足时保留本次候选目录供排查。

跨核参考敏感性计算要求两种方法均按 32 个计划输入原顺序提供估计；仅 `NaN` 表示不可用拟合，无穷值作为无效估计显式报错，不得被悄悄过滤。输出分别保留两方法有效数、共同有效数和计划分母；共同有效不足或区间不可估时不判定排序。合成测试覆盖非对称缺失、无穷值、完全缺失及参考范围或损失计算溢出；这不替代正式失败原因对账。

分析入口还提供按 32 个冻结输入哈希对齐的辅助函数，拒绝未知或重复标识，并返回两方法各自缺失的标识。哈希须由调用者与实际输入数组核对；仅有数组长度或字符串相同不能证明配对关系，失败原因仍由独立账本保留。该辅助函数尚未接入正式揭盲流程。

资格回执本身只声明身份、`passed` 状态及 880 项数量，不自动审查配对路径、预测封存或资源账。必须先完成独立逐项对账和科学验收，才能签发真实回执。Windows 交接中的 `audit_qualification.py` 可辅助检查台账和文件哈希，但它本身不是科学通过判据。模拟或手工填数回执不得用于正式封存。

真实参考封存还必须提供 `--qualification-ledger` 与 `--qualification-artifact-root`。封存器先根据预定清单逐项对账，并核对台账引用的证据文件哈希；880 项均须有已终结的尝试，失败及重试保留。Windows 资格回执须包含同一账本的 `ledger_sha256`。账本和对账摘要会复制进封存目录，后续入口复核哈希、阶段数量及首轮失败数，并绑定清单和对账程序的源码哈希。对账只验证账目与文件完整性，不验证文件内容的科学正确性或取代独立资格判定；原始证据仍需妥善归档。

真实候选输入的封存入口额外要求 Windows 资格回执明确标注 `scope: prospective_windows_qualification`、容量回执标注 `scope: prospective_capacity_budget`，两者均须标注 `evidence_kind: actual`；被标为模拟的回执不得用于真实候选。真实候选预检和 ODE 点检也必须具有各自的真实候选范围标记。新版本用模拟输入生成的链身份标为 `synthetic_test`；历史模拟链可能使用旧身份标签，须结合原始合成输入及模拟封存识别，不能作为正式链。上述字段只是防止误用的类型检查，不证明回执内容真实或科学上通过；仍须独立核实原始记录。代码变更后旧封存记录的源码哈希不匹配，必须按协议重新验收，不能覆盖旧记录。

候选真实 ODE 的 21 个固定点、每点三个 Hv 方向已额外对照 SciPy 灵敏度并通过，见 `ode-points.json`。最大状态误差 1.93e-10，最大后验差误差 1.55e-8，最大梯度和 Hv 误差分别为各自门槛的 0.000612 和 0.000477，独立参考收紧误差不超过预算的 0.000088。正式放行还需要完整数值验收、给定配置的连续/跨进程链校验、结果函数和存储验收，并核对整个研究的正式冻结与 Windows 资格结果。候选通过点检本身不足以完成正式科学协议封存。

## PyTorch 目标对照

已实现 PyTorch 层级 logistic 目标及静态核验入口。Mac CPU 上九个点与独立 NumPy 密度、梯度和 Hessian–向量积对照通过，见候选目录的 `torch-logistic-cpu.json`。首版使用默认 softplus 时极端点超出容差，其失败证据保存在 v1 候选目录。改为 float64 logaddexp 后通过。Windows CPU/CUDA 与采样路径待实际验收。

Mac CPU 上层级 logistic 还完成四链、23 步、W=8 的固定数组采样对照。顺序 RWM、Online Picard、顺序 MALA、quasi-DEER 的独立 NumPy 接受事件失配均为零，分别与同核顺序路径的最大差为 4.34e-19 和 1.32e-12。结果和实际随机数组见 `torch-logistic-sampler-cpu-v2.json` 及其相邻 NPZ；这只验证短链与窗口尾部。
