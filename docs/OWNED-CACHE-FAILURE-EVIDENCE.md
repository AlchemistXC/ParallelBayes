## 修正的问题

原成功归档接收入口要求每项任务都有封存的数值测量文件。导入、准备、写盘或管理进程
中断可能发生在这些文件形成之前。直接跳过缺文件任务会缩小计划分母；把缺测时间填零
会低估消耗。另外，四份数值调用都有效并不意味着外层任务已完整封存。
新增反例确认：旧统计接口在这种外层中断情况下仍会产生一个可用缓存测量点。

`OwnedCacheEvidence` 从校验和固定的布局文件和静止登记快照读取完整计划。
所有读取均使用归档内相对路径，原绝对路径仅保留为任务身份。每个测量探测都必须有
明确位置；不准删掉未启动、失败或中断项，不运行操作系统恢复、不生成随机数，
也不重复采样或独立路径核验。

返回的 `measurement_available` 与 `cached_seconds` 只在外层完成、全部规定调用
具有合格数值输出及费用记录时可用。`numerical_summary` 仍保留内层调用的事实，
因此“内层全部有效而外层未完成”可以被清楚表达。`samples_eligible` 永远为 false。
缓存探测不能重试以凑足三次成功重放。

| 情况 | 保存与分析处理 |
|---|---|
| 未登记或磁盘预检拒绝 | 计划行保留为 not_run；拒绝调用费用另留，不冒充执行器时间 |
| 完整合格测量 | measurement_available；保存原数组、审计、逐调用及外层费用 |
| 有限迭代导致数值失败 | 保留所有已执行调用与失败类别，不形成可用缓存点 |
| 准备资源拒绝或进程 RSS 保护 | 保留资源失败；尚未执行的调用仍为 not_run，不伪造数值记录 |
| 候选写盘后中断 | 从已保存回执保留费用与原数组；未完成审计的候选不变成合格轨迹 |
| 内层完全封存后外层中断 | 保留有效调用事实，但缓存点资格为 false |
| 管理进程退出、工作进程随后结束 | 使用登记中已观察到的进程结束回执；未封存的整体时间保持未知 |

统计入口对受管理测量要求每项都有 `task_outcome`。完整任务与调用状态必须一致，
不同任务类别不能混用。任务级资源失败、数值失败、中断与未运行分别计数；已知调用
费用始终保留，不能用外层未知时间推算零费用。原未带此字段的历史分析接口行为保留，
重建原冻结结果仍应使用其原提交。

## 重建与交付

本地完整包 `owned-cache-intake-v1.tar` 含两个原归档、只读伴随结果、最终故障夹具、
原始检查日志、源码快照、自包含 Git bundle 和逐成员清单。原始故障夹具中有明确标识的
故意损坏副本，不能与性能实验数据混用。体积与 SHA256 见
[归档回执](../benchmark/analysis/outputs/owned-cache-intake-v1/archive-receipt.json)。
大包尚未上传或公开发布；Git 内摘要不能替代完整原始证据。

从独立解压的分析源码根目录执行：

```text
python scripts/completion/validate_owned_cache_intake.py audit --output EXTRACTED_EVIDENCE
```

对其他受管理测量，先创建 `owned-cache-evidence-v1` 布局，固定协议、分配、输入、
登记快照及其哈希，为每个计划探测声明原任务身份、相对归档位置和调用账本位置。
调用 `OwnedCacheEvidence(root, descriptor, descriptor_sha256)`，再按 `probe_ids`
逐项 `read_probe`。把返回的 `binding` 和 `observation` 接入缓存配对统计；不要只提取
成功行，也不要将 `numerical_summary` 中的候选中位时间当作对外可用缓存点。
快照必须在合作运行器静止并持锁时取得；不能覆盖活动注册表。

Windows 后续仍按 F2 → F3 原生管理与有限技术批次 → 候选安装执行。
本接口目前接收已核验的 Mac 登记布局；Windows 如采用新登记 schema，应明确适配并
实际核验，不能伪装成 Mac 的进程组证明。正式主网格与缓存伴随网格仍未启动。
