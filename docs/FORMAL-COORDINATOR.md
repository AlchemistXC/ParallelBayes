# Mac共享任务登记与遗留进程保护

2026-10-05。源码与实际运行固定于`6d686de6e066234f962139cdd3a02c8a749a4137`。本次沿已授权的正式运行接口使用TDD和codebase-design，完成有限Mac调度接口核验；**不是正式推断实验，也不证明原生Windows已通过。**

## 当前接口与保证边界

`scripts/completion/formal_coordinator.py`提供`TaskCoordinator(host_lock)`，以及`run`、`retry`、`history`三个入口。所有合作调用者必须使用同一绝对主机锁路径；登记目录和第二层协调锁由它确定，不能由每个输出目录分别选择。

SQLite登记保存固定协议/任务ID、完整请求、工作程序及运行环境身份、原输出位置、至多一次显式重试的关系和追加事件。新任务先登记再调用历史运行器；管理进程退出后，下一调用检查登记中的未决进程组。活进程、观察权限不足或没有进程收据时均拒绝启动其他合作任务。只有操作系统报告原进程组不存在后，才能解除这项阻止；锁文件、PID文件、完成声明或等待超时本身不构成死亡证据。工作程序已退出而其同组子进程仍活着的情况也被拒绝。

初始身份使用“协议ID＋任务ID”，完整字段、请求、资源阈值和目的地另外固定；修改字段不会被当成新的任务。历史完成和失败均不会自动重跑。`retry`仅连接已验证的显式基础设施中断恢复接口，使用原输入和唯一重试位置；数值失败和已声明的工作程序失败不得借此替换。未知耗时保持未知，多次尝试不增加独立统计重复数。

历史运行器明确在启动前抛出的磁盘不足或主机锁占用，与已经启动的中断分开登记。前者不计作采样尝试，也不计作科学失败；资源条件满足后以同身份显式恢复。若管理进程在登记与进程收据之间突然退出，仍无法仅凭缺少文件证明没有启动，故保持拒绝；不自动清除登记。

登记采用事务和完整同步写入。全局启动检查只扫描未决记录；访问某任务时验证其事件链和证据，不为每个新任务重新读遍全研究的历史数组。校验和用于发现损坏，不构成抵抗同时篡改数据与校验和的安全证明。

## 行为核验及修复

新增5项公开接口行为检查通过；受影响的恢复4项、成本3项也通过，共12项，不把重复运行累计成新测试。新增检查覆盖：

1. 实际终止人工管理进程，活着的工作进程阻止另一个输出目录启动；进程组实际消失后允许独立任务继续，原未封存成本保持未知。
2. 原输入显式重试一次，保留原文件和两次已知成本，终态再次调用不执行；改变目的地、请求或同ID字段会被拒绝，数值失败不能重试替换。
3. 实际磁盘预检拒绝不造成虚假的存活任务，不妨碍其他符合资源条件的任务。
4. 已完成父进程的存活子进程仍阻止新任务。
5. 人工删除进程收据或损坏登记事件会被拒绝；管理层未封存的明确工作程序失败也不能重试。

开发中两项有实质意义的红灯记录得到修复：资源等待原先被误留作可能存活的任务；完整任务字段参与主键原先允许相同协议/ID经字段变化成为另一任务。另两次初始红灯对应尚未实现的调度模块与显式重试入口。最后两项扩展检查在已有实现上直接通过，没有虚构其先失败过程。失败日志、最终JUnit和人工样例均归档。

```text
python scripts/completion/audit_formal_coordinator.py --protocol benchmark/protocols/formal-runtime-technical-mac-v1.json --inputs TECHNICAL_INPUTS --output NEW_OUTPUT --rscript RSCRIPT --r-library R_LIBRARY --host-lock TECHNICAL_HOST_LOCK
```

`TECHNICAL_INPUTS`必须是该依赖协议封存的两份实际数组。源码自检要求Git中已提交的对应文件；这不是允许修改归档路径后直接对旧任务做恢复的入口。
