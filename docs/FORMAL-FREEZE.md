# 正式输入准备与封存接口

2026-10-07。源码 `ec3d8a1` 新增正式输入准备流程，沿用完整 v0.2 设计。**本轮没有执行 Windows 冻结，没有生成1,152份正式输入，没有新增MCMC或正式统计重复。** 原生运行器组合、正式worker与分批执行入口仍待接通；当前代码不是新的Windows交接提示词。

此前技术入口 `technical_batch.py` 的27主任务/24探测限制保留。新增模块用于正式研究，不更改历史数值内核、输入或协议。

## 实现内容

- `scripts/completion/formal_freeze.py`：一次生成、保存和重读一份实际输入，核对五种角色、形状、dtype、有限性、Rademacher方向、M1初值和NUTS地址。封存前检查全量任务计划及1,152份输入覆盖，保存文件与数组哈希。
- 已核验输入恢复时只核对原文件，不再次调用随机数生成器。磁盘不足在生成前拒绝；失败写入保留，普通resume不会覆盖。显式指定输入和原因后，允许将未封存的失败文件连同哈希归档，再按完全相同的源码、环境、身份和随机地址重新物化。已核验输入即使损坏也不允许使用该路径重生成。
- `scripts/windows/prepare_formal_study.py`：原生Windows准备入口，核对干净Git提交及规范源码字节、RTX5080 float64框架探针、Python依赖、R/posterior、共同主机锁及原生Job登记。保存源快照、依赖锁、设备记录和水井上游八文件，包括许可证；保留旧venv冻结标记。
- 科学设计保持九目标、四预算、128次四链重复、41,472主任务及9,216预选缓存探测。生成文件地址与任务表固定，不查看采样结果。正式计划文件、协议和最终封存标记分开；最后才写入 `FROZEN.json`。
- `verify_sealed_study()` 为跨平台只读入口，逐文件校验并重建完整协议。封存标记明确不授予采样执行资格，正式运行器还必须验证相应原生验收证据。

准备阶段使用原技术版本已有的8GiB采样RSS观察阈值、12GiB Job提交内存限制和每任务4GiB磁盘启动储备；本轮未在Windows重新验证这些限制。输入准备另要求12GiB可用RAM、首次具有全部未压缩主输入加8GiB余量，每文件保留4GiB磁盘储备。它们是拒绝条件，不保证全部输出、元数据及归档都能装下，也不是已观测进程内存上界。完整正式存储与运行成本仍须由执行器记录。

## 本地检查证据

最终 **8 passed，0 failed，0 skipped**；首轮7项和新增恢复后的8项日志均保留，不相加为15项。检查覆盖：

1. 已保存输入重开时不调用RNG，原文件不变；原数组文件被改动时拒绝。
2. 写入中断保留partial和intent，普通恢复不覆盖或重新生成。
3. 磁盘拒绝发生在intent和RNG之前，释放资源后可继续。
4. 显式未封存恢复保留失败原件并复用原随机地址，拒绝重做已核验输入。
5. 来源绑定、越界路径、非规范路径和错误方向数组被拒绝。
6. 一份人工命名的最大G2输入（四链、16,896步、64维）实际写盘、重读并逐角色核验。
7. 元数据层构建全部41,472主任务并通过原公共 `BatchPlan` 胶囊核验；缺少输入、缩小输入集不能封存。
8. 非Windows平台在创建正式目录和主机锁之前拒绝原生准备命令。

最大尺寸检查是储存夹具，不是新的科学重复。其逻辑字节、实际文件字节、哈希及测试来源写在 `benchmark/analysis/outputs/formal-freeze-v1/RECEIPT.json`。该检查没有运行采样器；同随机地址的一致性也不作为一般随机流独立性证明。
