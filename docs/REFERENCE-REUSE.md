# 历史Mac参考用于后续Windows推断评价的资格核查

2026-10-05｜F3准备性审计｜没有新增采样，也没有回写Windows-v1原来的参考状态

`scripts/completion/audit_reference_reuse.py`核对了两个冻结协议、模型规范、数据、参数顺序/坐标、8次参考任务、所有原始文件与原汇总的哈希。L1/L2的Mac参考模型与Windows目标规范完全相同，8次保存结果的目标ID一致。重新从实际样本计算四个函数的均值、批均值MCSE及拟合间MCSE，均复现原汇总（绝对/相对容差`1e-12`）。

共同函数按原顺序为`q1`、`q2`、`sigmoid(q1)`、`q1>0`。每个目标来自4次独立参考拟合，每次4链×16384个保留抽样；262144个相关抽样不能称作262144个独立参考重复。参考与Windows任务的已记录随机种子命名空间分离，不能仅凭整数不同证明所有伪随机子流的独立性。

| 目标 | 参考MCSE：四个函数，顺序同上 | 可复用范围 |
|---|---|---|
| L1 | 3.890e-4、5.002e-4、9.406e-5、7.640e-4 | 四个函数的有限参考，仍需传播参考误差和保留共同偏差局限 |
| L2 | 8.893e-5、1.019e-4、2.169e-5、未确定 | 前三个函数可作有限参考比较；全函数精度判定仍未确定 |

这里MCSE取原方案的批均值与拟合间估计较大值，没有把结果称为解析真值。L1最后一个事件28624次为正；L2同事件全部为零，不能以零样本方差替代概率不确定性。没有删除该函数，也没有用独立Bernoulli公式对相关链给出伪精确上界。

这一步消除了“L1/L2是否同一个后验”的疑问。后续新协议可以引用本参考身份及其原始文件，L1不必为了换平台重新制造另一份真值。L2若无法补得合格的稀有事件参考，仍应保留未判定结果；它不必阻止其他目标的推断比较。只有新协议冻结之后的实验才支持新的精度/成本结论。

重建命令（`CPU_REFERENCE_RUN`为历史复现包中的`benchmark/runs/cpu-reference-v1`）：

```text
python scripts/completion/audit_reference_reuse.py --reference-run CPU_REFERENCE_RUN --output NEW_OUTPUT
```
